# baozi.space V2 · 决策记录

**最后更新：** 2026-08-13

**规则：** 这里只记录已经确认、会约束后续工作的决策；想法和待讨论项放在 PRD 的 Open Questions 中。

## 已确认

### D-001 · 产品身份

- **状态：** Accepted
- **决策：** `baozi.space` 是包子的个人档案与数字手账，不是餐饮站、SaaS、应用启动器或传统履历作品集。
- **影响：** 产品首先帮助访客理解“包子是谁、记录什么、最近有什么”，视觉隐喻不能压过内容。

### D-002 · 最终视觉论题

- **状态：** Accepted
- **决策：** 选定 `binder-archive（活页档案）`，不再继续 printed-archive、independent-issue、collected-life 三个方向。
- **启动页：** 桌面场景中的透明活页本与堆叠卡片；卡片可以受控抽取阅读。
- **主页：** 使用稳定横线、日期轨、重复条目和内容绑定插图形成周记式阅读骨架；黑色正文配一处橙色强调。更自由的拼贴语言只进入固定强调槽位，不支配整页。
- **说明：** “周记式”是视觉节奏，不代表固定周更机制。
- **影响：** 旧麻布封面、自由拼贴首页不再是 V2 的设计来源。

### D-003 · 内容结构优先于装饰

- **状态：** Accepted
- **决策：** 保留此前方向 B 的清晰阅读秩序：身份与目的 → 最新/精选内容 → 栏目索引 → 最近更新 → About。
- **影响：** 启动页必须输出信息，不能只是进入网站前的气氛门。

### D-004 · 八栏目与稳定 URL

- **状态：** Accepted
- **决策：** 保留 Blog、Thoughts、Photos、Drinks、Books、Music、About、AI Works 八个栏目及现有 URL。
- **影响：** 视觉可调整，但不能破坏直接访问、刷新、返回、收藏和分享。

### D-005 · 用户拥有正式内容

- **状态：** Accepted
- **决策：** 各页面呈现的个人事实、正式介绍、栏目定位、作品说明、联系信息、内容照片和作品原件由用户提供。
- **Codex 边界：** 负责定义页面需要哪些字段、指出缺口、整理结构，并在用户提供原始信息后协助润色；可按用户批准的 Style Recipe 制作装饰性或生成式 UI 资产，但必须由用户最终批准；不得虚构用户经历或把占位文案视为正式内容。

### D-006 · 先定义、再设计、后开发

- **状态：** Accepted
- **顺序：**
  1. Phase 0 基线；
  2. Phase 1 PRD、信息架构与用户内容输入；
  3. Phase 2 设计规范与图片 Style Recipes；
  4. Phase 3 交互风险原型；
  5. Phase 4 高保真设计确认；
  6. Phase 5 正式开发；
  7. Phase 6 内容与 QA；
  8. Phase 7 Cloudflare 发布。
- **影响：** 高保真设计确认前不修改正式页面实现。

### D-007 · 设计确认不只看静态图

- **状态：** Accepted
- **决策：** 启动卡片抽取、打开活页本、页面翻页必须通过“关键静态状态 + 可点击原型”共同确认。
- **影响：** 单张首页效果图不能作为开发放行依据。

### D-008 · 技术与内容资产保持可迁移

- **状态：** Accepted
- **决策：** 继续以 Astro 静态输出、Markdown Content Collections、Git 和语义 URL 为基线；动效是渐进增强。
- **影响：** 不为卡片和翻页引入重型 3D 物理引擎；无 JavaScript 与减少动态效果时仍可访问内容。

### D-009 · 项目管理与事实来源分离

- **状态：** Accepted
- **决策：** Git 中的 Markdown 是 PRD、规范和验收要求的事实来源；Linear 负责里程碑、状态、依赖和执行。
- **影响：** PRD Phase 1 通过后再把稳定工作拆入 Linear，避免过早产生大量失效任务。

### D-010 · 发布平台

- **状态：** Accepted
- **决策：** 最终通过 Cloudflare Pages 部署；开发阶段先使用预览部署，通过 QA 后再绑定 `baozi.space`。
- **影响：** 上线必须保留 Git 回滚点，不直接用生产域名评审未完成设计。

### D-011 · 网站品牌与基本隐私边界

- **状态：** Accepted
- **决策：** 网站主名称为“中华一番包子铺”；它承载“包子的空间”这一个人数字花园概念。
- **个人署名：** 所有作者、About 自称、身份卡和版权署名统一使用“包子”。
- **隐私边界：** 不公开用户真实姓名，不公开家人的姓名、照片、身份及其他可识别信息。
- **影响：** 页面、元数据和视觉资产使用网站名称；涉及具体个人时使用公开署名，不混用品牌名。

### D-012 · Work / Life 双线身份

- **状态：** Accepted
- **决策：** 个人身份不只由职业定义，正式内容按 Work / Life 两条线组织。
- **Work：** 前小红书商业化早期员工，曾开拓旅游出行、游戏、小红书电商等多个行业；对外使用“懂一些营销，也懂一点产品”的克制表达。
- **Life：** 立志做一个生活家，持续记录对工作与生活的思考；兴趣包含料理、运动与摄影。
- **当前关注：** 最近学习投资与交易；这是会变化的信息，不固化为永久身份。
- **影响：** 启动页只承担快速身份识别；主页使用 Work / Life 摘要；完整经历、兴趣和当前关注在 About 中展开。

### D-013 · 启动页内容与回访策略

- **状态：** Accepted
- **出现频率：** 每个浏览会话只自动显示一次，使用会话级本地保存并在关闭标签页后失效；从栏目或详情返回 `/` 时直接进入主页。
- **主动重看：** 主页提供“合上本子”入口。
- **卡片结构：** 四张核心信息卡为身份、网站用途、最近更新、栏目目录；另放 3–5 张图片插页，八栏目不拆成八个独立交互目标。
- **交互边界：** 最近更新卡和栏目目录卡可以导航；身份卡与用途卡只阅读；图片插页可以查看完整图案或大图，但默认不导航。
- **主按钮：** 使用“打开本子”，替换原型中的“进入档案”。
- **更新时间：** 启动页显示全站公开且已批准内容中最大的 `updated ?? date`。
- **影响：** Phase 2 可以调整纸片数量、重叠和材质，但不得改变核心信息集合、导航责任和回访规则。
- **后续更新：** D-014 将原“八栏目”调整为七个内容栏目 + 独立 About；栏目集中在目录卡、不拆成多个启动交互目标的规则继续有效。
- **已被后续决策更新：** D-025 替代本条的“卡片结构、导航责任、启动页更新时间”部分；本条的会话频率、“合上本子”和“打开本子”文案仍有效。

### D-014 · V2 内容分组调整

- **状态：** Accepted
- **主栏目：** Blog、Photos、Project。
- **次栏目：** Drinks（喝酒记录）、Books、Music、Movies；Books / Music / Movies 可在视觉与内容组织上形成“书影音”组。
- **About：** 使用主页独立摘要和完整 About 页面，不占据内容主入口。
- **替代关系：** 本决策替代 D-004 中 Thoughts 和 AI Works 继续作为 V2 顶层栏目的部分；当前生产路由仍作为 Phase 0 事实保留，迁移目标和永久跳转等待 Phase 1 最终确认。
- **影响：** PRD、内容 schema、栏目导航、现有内容迁移和 URL 重定向都需要按新分组调整；正式代码在 Phase 5 前保持不变。

### D-015 · Books / Music / Movies 分页

- **状态：** Accepted
- **决策：** Books、Music、Movies 使用三个独立页面，不新增统一“书影音总览”页。
- **共性：** 三页可以共享“顶部统计与热力图 → 最近状态 → 人工推荐 → 完整归档”的信息骨架和基础组件。
- **差异：** 热力图事件、统计指标、最近内容数量和视觉细节必须按阅读、观影、音乐三种行为分别定义，不能为了复用组件强行统一数据含义。
- **影响：** `/books`、`/music`、`/movies` 都是可直接访问和分享的完整页面；Phase 2 为三页建立同源但不完全同形的设计规范。

### D-016 · 书影音热力图事件口径

- **状态：** Accepted
- **总规则：** 热力图统计“完成或主动记录事件”，不统计阅读时长、单曲播放次数或流媒体播放量。
- **Books：** 每条书籍记录最多贡献一次，优先使用读完日期；没有读完日期时使用主动建档日期。
- **Movies：** 每次实际观看完成贡献一次，重看可以作为新的观看事件。
- **Music：** 每条主动记录的专辑或歌单贡献一次，逐次播放不计入。
- **影响：** 三页可以共用热力图组件，但需要各自的事件映射；数据模型必须避免同一书籍或音乐记录被重复计数。

### D-017 · 书影音热力图时间范围

- **状态：** Accepted
- **默认范围：** 当前自然年 1–12 月。
- **历史浏览：** 允许切换往年，不制作一张无限延伸的全历史热力图。
- **统计关系：** 热力图上方分别显示本年数量和全部累计，不能用单一总数替代年度语境。
- **日期状态：** 当前年份中的未来日期显示为空白纸格，不计入活跃度。
- **影响：** 三个页面使用相同的年份切换逻辑；统计和热力图必须基于同一时区与事件日期规则。

### D-018 · 书影音最近状态数量

- **状态：** Accepted
- **Books：** “正在读”显示 Top 3。
- **Movies：** “最近看过”显示 Top 5。
- **Music：** “最近在听”显示 Top 5。
- **桌面端：** 完整展示对应数量。
- **手机端：** Books 直接展示 3 条；Movies / Music 默认可见前 3 条，后 2 条通过隐藏滚动条的横向轮播访问。
- **交互边界：** 轮播不自动播放；必须保留下一项露出或位置提示，并支持触摸、触控板、键盘和辅助技术，不能因隐藏滚动条而隐藏可发现性。
- **影响：** Phase 2 需为 Movies / Music 定义移动端卡宽、间距、滚动吸附和提示样式，并验证 390px 与键盘操作。

### D-019 · 书影音人工推荐规则

- **状态：** Accepted
- **结构：** 每个 Books、Movies、Music 页面使用 1 个重点推荐 + 最多 4 个普通推荐。
- **编辑权：** 推荐全部由包子人工选择，不根据平台评分、热度或算法生成。
- **内容要求：** 每条推荐必须包含一句“为什么推荐”。
- **更新频率：** 不强制按月更新，可以作为长期精选保留。
- **不足状态：** 少于 5 条时展示实际数量，不补占位卡或自动推荐。
- **影响：** 内容模型需表达推荐状态、顺序和推荐理由；同一栏目中只能有一个重点推荐。

### D-020 · 书影音栏目主页与完整归档

- **状态：** Accepted
- **栏目主页顺序：** 年度统计与热力图 → 最近状态 → 查看全部记录入口 → 页面底部人工推荐。
- **完整归档：** 使用 `/books/archive`、`/movies/archive`、`/music/archive`，负责年份、状态、标签筛选和完整列表。
- **边界：** 栏目主页不继续展开无限历史列表，避免人工推荐被大量旧记录压到页面过深位置。
- **链接要求：** 栏目主页与完整归档必须互相可达；归档中的每条记录仍使用稳定详情 URL。
- **影响：** `archive` 成为三个栏目下的保留路径，内容 slug 不得使用 `archive`；Phase 2 需分别设计概览页和高密度归档页。

### D-021 · V2 目标路由与旧 URL 迁移

- **状态：** Accepted
- **新增目标路由：** Project 使用 `/projects`，Movies 使用 `/movies`。
- **栏目合并：** Thoughts 并入 Blog；AI Works 并入 Project。
- **旧内容链接：** `/thoughts/*` 和 `/ai-works/*` 按内容逐条永久跳转到新详情 URL，不能只跳到栏目首页。
- **About：** `/about` 直接作为完整 About 页面；旧 `/about/me` 永久跳转至 `/about`。
- **影响：** D-004 的旧 URL 继续作为兼容入口而不是 V2 顶层栏目；Phase 5 必须先建立迁移清单和重定向测试，再移除旧路由模板。

### D-022 · 主页人工精选与回退

- **状态：** Accepted
- **首要内容：** 优先展示全站唯一一条 `featured: true` 且公开、已批准的内容；精选可以来自任意栏目。
- **唯一性：** 同时存在多于一条有效精选时阻塞发布，不由系统按日期或 slug 猜测。
- **回退：** 没有有效精选时，只从 Blog、Photos、Project 三个主栏目中选择 `updated ?? date` 最新的公开且已批准内容。
- **次栏目：** Drinks、Books、Music、Movies 可以进入最近更新，但不自动占据主页首要位置。
- **影响：** Phase 5 需要全站精选唯一性校验，并为无精选、主栏目无内容的情况提供用户批准的空状态。

### D-023 · 主页最近更新

- **状态：** Accepted
- **数量：** 固定最多 3 条。
- **来源：** 全部七个内容栏目中的公开且已批准内容。
- **排序：** 按 `updated ?? date` 倒序。
- **去重：** 排除当前主页首要精选，避免同一内容重复出现。
- **显示字段：** 栏目、日期、标题和一句摘要。
- **不足状态：** 少于 3 条时显示实际数量，不补占位；没有可用内容时隐藏整个区块。
- **影响：** 最近更新不使用手工排序；Phase 5 需要对精选排除后的结果进行稳定排序测试。

### D-024 · 主页 About 摘要

- **状态：** Accepted
- **文案：** 直接复用已确认的 Work / Life 两段短介绍，不另写主页专用身份文案。
- **Work：** 前小红书商业化早期员工，懂一些营销，也懂一点产品。
- **Life：** 立志做一个生活家，持续记录文字、料理、运动与摄影。
- **入口：** 使用“继续认识包子”链接到 `/about`。
- **边界：** 具体行业经历和“最近学习投资与交易”等可变信息只在完整 About 展开。
- **影响：** 启动页、主页和 About 共用同一事实源，避免多套身份文案随时间产生冲突。

### D-025 · 启动页内容范围收敛

- **状态：** Accepted
- **决策：** Launch 只呈现两张信息卡：网站简介与 About Me。
- **内容边界：** 网站简介卡说明“这里是什么、为什么建立这个网站”；About Me 卡使用公开署名与一句话身份说明“包子是谁”。
- **导航边界：** 网站简介卡只阅读；About Me 卡使用真实链接进入 `/about`。
- **不在 Launch 显示：** Blog、Photos、Project、Drinks、Books、Music、Movies 的目录、最近更新、全站更新时间或各栏目更新时间；这些信息统一由 Home 承担。
- **图片插页：** 是否继续保留 3–5 张纯图片插页仍为 Phase 1 Open Question；若保留，只承担审美展示和大图查看，不承担内容信息或栏目导航。
- **替代关系：** 本决策替代 D-013 的四张核心信息卡、最近更新/目录导航和启动页更新时间；D-013 的会话频率、主动重看与主按钮文案继续有效。
- **影响：** Phase 2 必须围绕两张信息卡建立视觉层级，不得从旧原型恢复栏目卡或动态更新卡。
- **后续更新：** D-027 已关闭本条的图片插页 Open Question，确认采用方案 B。

### D-026 · 七栏目非空生产门禁

- **状态：** Accepted
- **生产门禁：** Blog、Photos、Project、Drinks、Books、Music、Movies 必须分别至少有一条 `draft: false && approved: true` 的真实内容，任一栏目为零即阻塞 V2 生产发布。
- **一致性：** 主栏目与次栏目应用完全相同的内容真实性、用户批准和数量门禁；主次只影响主页视觉层级。
- **内容边界：** 现有占位条目不展示、不计数；不生成假文章、假记录或算法填充内容来满足门禁。
- **防御性回退：** 预览、迁移或异常状态中的空栏目保留稳定 URL，页面及主页目录显示“正在整理”，设置 `noindex`，并排除在人工精选、最近更新和全站更新时间之外。
- **自动恢复：** “正在整理”和 `noindex` 由公开且已批准内容数量派生；第一条有效内容发布后自动取消，不维护独立人工状态。
- **影响：** Phase 5 需要实现统一有效内容计数和派生状态；Phase 6–7 在构建或部署前校验七栏非空。`content-approval-register.md` 中的占位内容不能作为首发样本。

### D-027 · 启动页采用装饰图片卡方案 B

- **状态：** Accepted
- **选择：** 采用独立解释 Demo 中的方案 B：两张正式信息卡之外，保留若干装饰图片卡（此前称“纯图片插页”）。
- **数量边界：** Demo 以 3 张为基线；Phase 2 可依据桌面与手机构图在 3–5 张之间确定最终数量，但不能全部取消。
- **内容职责：** 装饰图片卡只展示照片、插画或纹理，增加层次、遮挡与收藏感；不得承载栏目说明、最近更新、全站更新时间或其他动态信息。

### D-112 · A1 录屏反馈移除狗绕圈并修正绳索与动作分段

- **状态：** Accepted（2026-08-14，依据用户对 1280×720 实际录屏的复核反馈）
- **用户确认问题：** 追逐过程中的牵引绳没有稳定连接人物手部与小狗项圈；部分人物帧视觉尺寸发生突跳；进入首页后的小狗绕人物运动不符合目标。用户希望未来人物与小狗的头部随鼠标移动，但具体素材与交互方案后续再讨论。
- **根因与修正：** 牵引绳 SVG 固定使用 1440×900 viewBox，却接收当前舞台 CSS 像素坐标，导致 1280×720 等视口发生二次缩放；端点 Y 又使用经验比例而非角色真实位置。运行时现按实时舞台尺寸更新父 SVG viewBox，并以角色 `offsetTop`、Sprite 尺寸和逐帧 hand / collar anchor 计算端点。人物从 run 切换 trip 时此前错误沿用 0.25–0.82 总进度，导致 `personTrip` 从后半帧开始；现改为 run、trip、stand 三段局部进度，各动作从第 1 帧进入。
- **收尾行为：** 0.94–1.00 的小狗 wrapper 椭圆绕圈已删除；`dogSettle` 只在人物脚边原地播放并停下。旧 D-106 / D-110 中的“完整绕圈”描述保留为历史，执行时由本条覆盖。
- **头部跟随边界：** 当前 final still 与站立 Sprite 均为扁平合成 WebP，不具备独立头部、颈部遮挡补画和 pivot anchor。素材方案未确认前保持人物与小狗静止，不使用整角色平移/旋转冒充头部跟随；该交互继续阻塞 A1 最终视觉批准。
- **验证契约与结果：** Playwright 新增 1280×720 实时 SVG viewBox、Manifest 逐帧 anchor 到 SVG 路径首尾点 `<1px`、trip 首尾帧和狗静态收尾断言；最终 unit 9/9、Playwright 16/16、Astro check 0 error、静态构建 24 页通过。后续录屏仍需人工确认 Sprite 自身是否存在剩余尺度漂移；若局部进度修正后仍存在，必须由下一版生产素材统一帧内人物比例，不在运行时添加逐帧特例缩放。
