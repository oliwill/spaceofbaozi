## 2 设计定位与边界

**已确认。** 中华一番包子铺是包子的个人档案、阅读空间和创作记录。“包子铺”保留为名称与轻度语言趣味，不把网站做成餐饮品牌。访客应能明确找到文章、照片、简历和项目，读完后知道如何返回。

视觉由低对比点阵环境、暖白内容纸、中文编辑排版和水彩剪纸人物构成。角色承担首页记忆点，正文承担长时间阅读。人物、小狗与草地继续使用已有 v2 素材，不为统一页面重画或换风格。

**已确认的禁止回退方向：** 不恢复实体手账封面、书脊、3D 翻书、桌面物件；不恢复 BaoziHand 或手写导航；不做自由拖拽拼贴和彩色便利贴式主导航；不为每个栏目另造一套视觉系统；不新增 Canvas、WebGL 或游戏引擎。React 和 Lenis 的旧禁令已被后续决策覆盖，不能再以旧文档拒绝当前架构。

**规范建议。** 同一种信息使用同一种字体、色彩与控件；首页与文档页可以有不同构图，但纸张材质、文字层级、四个入口名称、焦点样式与返回语义保持一致。任何装饰不得遮挡文字、阻断点击或改变内容的阅读顺序。

## 3 字体与排版

### 3.1 已有基础与需要确认的差异

**已确认：** D-136 去除手写 UI，导航与界面使用系统无衬线；D-148 采用已确认左侧导航/角色构图。

**代码现状：** 全局正文与标题为 `Songti SC / STSong / SimSun / serif`；导航为 `Microsoft YaHei / PingFang SC / system-ui / sans-serif`；部分数字使用随仓库提供的 IoskeleyMono Nerd Font。旧 design spec 写“思源宋体标题、无衬线正文”，但当前生产样式未按此完整落地。此差异需要显式收敛，不能宣称已经统一。

**规范建议 A：本轮保留宋体正文与标题、无衬线 UI、等宽元信息。** 理由是它最接近当前首页和已改造文章页，不新增字体文件，也避免统一修复变成整站换字。若包子希望恢复“宋体标题＋无衬线正文”，应作为独立选择确认，并用同一篇真实长文做桌面/手机对比。

### 3.2 建议字体 token

以下是建议归一后的字体栈，不是当前代码已经存在的 token。中文不加额外字距；英文和数字保留自然大小写，禁止为了装饰全部大写。

| Token | 建议值 | 用途与回退 |
|---|---|---|
| `--font-reading` | `"Songti SC", "STSong", "SimSun", Georgia, serif` | 中文标题和正文优先系统宋体；西文缺字时回退 Georgia/serif；系统差异需截图验收 |
| `--font-ui` | `"PingFang SC", "Microsoft YaHei", system-ui, -apple-system, "Segoe UI", sans-serif` | 导航、按钮、标签、状态、目录；中文优先平台系统字体，英文数字随同一 UI 字体 |
| `--font-data` | `"IoskeleyMono Nerd Font", ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", "PingFang SC", "Microsoft YaHei", monospace` | 日期、进度百分比、代码；中文回退无衬线，避免等宽字体缺字；数字使用 `tabular-nums` |

字重以实际字体支持为准。中文正文400，标题400或有真实字重时500，UI 400/500。当前 `font-synthesis: none` 禁止伪造粗斜体；不要再用不存在的700字重承担唯一强调。正文重点沿用克制的底色、字色或下划线辅助，仍须保证可读与可复制。图片中的手写标记不等于允许重新引入手写 UI。

新增 webfont 必须先确认授权、中文子集范围和首屏负载。未获批准时不新增字体下载；现有字体加载失败不得造成空白文字。

### 3.3 建议字号层级

以浏览器默认根字号16px为换算示例，实际实现使用 rem 与 clamp，不锁死用户字号。表中数值为建议；首页64/39px来自现有实现，其余用于收敛当前分散的字号。

| 层级 | 桌面 | 手机 | 行高 | 说明 |
|---|---|---|---|---|
| 首页主标题 | 4rem，64px | 2.4375rem，39px | 1.08 / 1.1 | 保留“你好，我是包子”断行；不机械套到每个栏目 |
| 栏目标题 H1 | `clamp(2.5rem, 5vw, 4rem)` | 2.25rem，36px | 1.15 | 建议从当前最高80px收敛到64px，待视觉确认 |
| 文章标题 H1 | `clamp(2.25rem, 4.5vw, 3.5rem)` | 2rem，32px | 1.2 | 长标题自然换行，不截断；当前最大73.6px，建议降到56px |
| 正文 H2 | 1.75rem，28px | 1.5rem，24px | 1.35 | 章节主节点，前距40–48px、后距12px |
| 正文 H3 | 1.25rem，20px | 1.125rem，18px | 1.4 | 前距28–32px、后距8–12px |
| 正文 H4 | 1.0625rem，17px | 1rem，16px | 1.5 | 不靠更淡的颜色降低可读性 |
| 导语 | 1.125rem，18px | 1rem，16px | 1.8 | 比正文简短，宽度不超过正文阅读列 |
| 正文 | 1.0625rem，17px | 1rem，16px | 1.85 / 1.8 | 段后20px；列表与正文同字号 |
| 导航与按钮 | 0.9375rem，15px | 0.875rem，14px | 1.4 | 点击区域至少44px高；文字大小与点击区域分别控制 |
| 日期与辅助信息 | 0.8125rem，13px | 0.8125rem，13px | 1.5 | 不延续当前首页9–11px的重要文字 |
| 代码与进度数字 | 0.875rem，14px | 0.8125rem，13px | 1.6 | 数字不因更新跳宽；代码块可独立横向滚动 |

**规范建议。** 正文容器上限720px，英文约65–75字符一行，中文以约35–42字一行为视觉检查目标；混排以实际字体量测，不把 `ch` 当成中文字宽。正文左对齐，不强制两端拉齐。长链接、代码和表格不把整页撑宽。200%缩放后保留内容和操作，不用横向缩小整张页面解决溢出。

### 4.2 对比要求

**规范建议。** 普通文字与实底至少4.5:1；大号文字至少3:1；表达控件与状态所必需的边界、焦点至少3:1。装饰点阵与纸纹不承担阅读或状态信息，可保持低对比。链接除颜色外使用下划线或其他稳定标记，当前栏目不能只靠色相区分。

使用标准 sRGB 相对亮度公式计算，以下为暖纸 `#fffdf7` 上的结果，四舍五入至两位。此表不代表整个站点已通过无障碍审计。

| 前景色 | 对比度 | 结论 |
|---|---:|---|
| `#25231f` | 15.42:1 | 正文与标题足够 |
| `#67635b` | 5.88:1 | 可用于普通小字 |
| `#284d5b` | 8.97:1 | 可用于链接和焦点 |
| `#b8513d` | 4.82:1 | 暖纸实底上可读；透明度降低后须重算 |
| `#8b857b` | 3.60:1 | 当前普通小字不足4.5:1，建议不用作小字 |
| `#839260` | 3.31:1 | 仅装饰或满足条件的大字，不作普通正文 |

半透明背景、图片叠字、渐变和 disabled 状态必须按实际合成背景检查。不要通过把整块文字 opacity 调低来制造层级。

## 5 布局与页面关系

### 5.1 共享基础

**已确认：** 桌面12列、移动4列的设计网格；点阵环境固定原点；内容落在暖纸上。一级入口统一为文章、照片、简历、项目，路线分别为 `/blog`、`/photos`、`/resume`、`/projects`。书影音与饮品继续按归档路由处理，不恢复 Shelf 主入口。

**规范建议：** 4px为空间最小单位，常用间距8/12/16/24/32/48/64px。局部控件12–16px，段落20–24px，内容组32px，章节48–64px。桌面网格槽24px，手机16px。基础样式集中维护，不再用每页不同的额外左边距叠加出排版。

### 5.2 首页与文档页可以不同

| 页面 | 保留的构图 | 与全站共享 | 不应混用 |
|---|---|---|---|
| 启动页 | 全视口点阵与草地，角色叙事，滚动驱动，可跳过 | 背景原点、角色尺寸契约、最终落点 | 不用文档左栏挤压舞台 |
| 首页 | 左侧点阵区放导航、人物与嘉乐；右侧暖白纸排身份与内容 | 纸色、字体角色、入口词语、链接与焦点 | 不恢复右侧人物或顶部纸索引布局 |
| 栏目页 | 左 sticky 导航，右内容纸；标题、说明、真实内容或空态 | 统一 Editorial 标题、间距、状态 | 不再叠旧 `paper-page` 折痕纸 |
| Blog详情 | 文档壳内单列阅读，返回入口，元信息、正文、前后篇 | 内容纸、阅读宽度、链接、历史行为 | 文内跳转不得被当作跨页翻书 |
| Photos详情 | 同一文档壳，摄影与说明优先，沿用灯箱 | 标题、返回、图片署名、焦点 | 不改变相册顺序，不放占位相片 |
| Resume | 身份、已确认经历、Now、联系方式 | 同一 Editorial 排版 | 不虚构字段，不公开工程说明 |
| Projects | 真实状态与项目介绍，详情按真实材料组织 | 同一 Editorial 排版与返回 | 不用假成果撑版，不把首页矩阵和列表入口混淆 |

### 5.3 尺寸与断点

**代码现状：** 桌面首页纸宽 `min(88vw,1360px)`、顶距28px、右对齐；手机纸宽 `100vw - 28px`。文档侧栏280px，内容纸顶距 `clamp(20px,4vh,48px)`，右边距 `clamp(20px,4vw,48px)`。手机文档页52px顶部导航、纸面贴边。布局在767px切换，页面遮罩却在640px切换。

**规范建议：** 按D-148统一首页/文档左栏与右侧纸面，具体尺寸按360/390及桌面验证；文档纸内的内容宽度取可用宽度与860px较小者，正文单独上限720px。列表标题与列表正文共用起始线，不用内容容器再加8vw左距。手机内容只由一层容器提供24px横向留白，避免 main padding 加页面 padding 的双重缩窄。

建议布局断点统一为 `<768px` 手机、`768–1199px` 紧凑桌面/平板、`≥1200px` 桌面。动效是否也统一到768px列为待确认；批准前保留现有640px机制，并单独检查640–767px区间。

**待确认：手机角色比例。** 本轮390×844画面中，角色明显偏小，中间空白较长。该手机顺序建议已由D-148与确认Demo取代：导航及角色位于正文上方点阵区域，导航四项单行，以角色区220–320px高度做对比，不根据桌面vw直接缩小整个人物。具体站位、大小与启动页交接锚点须联动评审，本文不先定一个未经验证的像素答案。

## 6 纸张与组件状态

### 6.1 纸面材质

**已确认：** 纸张与背景需要可感知边界，转场才看得见；D-145 的桌面内嵌纸面继续有效。纸面是2D阅读层，不模拟实体翻书。

**规范建议：** 桌面环境点阵24px间隔、手机18px；内容纸上不再铺同强度点阵。首页现有轻纸纹可保留到0.025不透明度，不能影响正文。文档纸边使用1px低对比分隔与柔和阴影；统一阴影建议为 `0 1px 2px rgba(43,38,32,.05), 0 24px 48px -24px rgba(43,38,32,.16)`。手机贴边文档纸移除大阴影与边框，依靠布局和导航分隔保持层级。

禁止将旧折痕、书脊、波浪标题线和印章标签套在新Editorial纸面内。引用块、代码块、标签可以有局部背景，但不能把每一段都做成独立悬浮卡片。

### 6.2 状态规则

下表是规范建议；保留现有语义标签和浏览器原生能力。

| 状态 | 视觉与行为 |
|---|---|
| 默认 | 链接可识别；四入口顺序一致；按钮使用明确动作词 |
| Hover | 只在支持hover的细指针启用；120–180ms色彩/下划线响应，位移不超过2px |
| 当前栏目 | `aria-current="page"`，深蓝文字加稳定线标；详情页仍标所属栏目 |
| 当前章节 | 与栏目状态区分，目录使用 `aria-current="location"`，文字/侧标同步 |
| Focus | 2px实线深蓝，外偏移3–4px；不被纸面overflow裁掉，不只靠hover可见 |
| Pressed | 沿用克制反馈；不缩小整个页面、不让文本位置跳动 |
| Loading | 保持现有正文或布局；指示只出现在正在操作的位置；不得白屏等待动效 |
| Empty | 一个清楚标题加一行说明；如“摄影正在整理”；不向访客解释审批门禁、代码文件或占位策略 |
| Error | 告知当前内容未能打开并给重试/返回路径；素材失败显示静态内容，导航失败可退回普通链接 |
| Disabled | 使用真正disabled/aria-disabled语义并说明原因；没有前后篇时省略对应入口，不展示可点假按钮 |

长标题换行、无封面、无日期、缺少项目状态或外链时，按schema和内容契约处理；不得自动编造事实。图片需要有意义的alt、可核验的来源与署名。

## 7 导航 返回与浏览历史

**已确认。** 首页与文档页共用左侧点阵区的文章/照片/简历/项目四入口；手机四项单行；品牌链接回 `/#home`，不重播开场。文章保留顶部返回、滚动超过360px后的固定返回，以及底部返回和前后篇（D-135）。文档页返回表现为纸面掀走，不再从下方升起（D-144）。

**规范建议。** “返回文章”始终去文章列表，不调用可能跳出网站的无条件 `history.back()`；浏览器后退/前进则尊重真实历史与滚动位置。文内目录点击生成可分享hash，并只为明确用户点击增加历史；自动滚动高亮不持续写历史。首次带hash打开、刷新、浏览器后退都落在同一章节，不被固定导航遮挡。

导航必须保留普通 `<a href>` 的语义；新标签打开、复制链接、禁用JS仍可访问。滚动到章节后，键盘操作应把焦点合理移到目标标题，不引发第二次意外滚动。不要截获全局上下方向键来强迫章节翻页，输入框、代码选择和辅助技术保持正常。

跨页时当前页面在下一页可用前保持可读。快速点击以最新有效目的地为准，旧导航回调不得覆盖新页面；跳转取消、失败或用户返回后清理遮罩与过期计时器。滚动实例、事件监听和导航显隐在页面交换后正确重建/销毁，不能继续控制已移除的DOM。

## 8 动效系统

### 8.1 每种动作表达什么

**已确认。** 开场用滚动讲角色故事；HomeOrbit响应角色区域的输入；文档换页用纸的进入/离开提示层级变化。持续阅读不要求用户等待动画。人物素材、滚动参数和场景交接仍受D-132的Manifest契约约束。

**规范建议。** 动效分为三层：场景叙事、路由切换、局部反馈。一次操作只允许一个主运动；章节点击不同时触发路由纸张飞入和长距离滚动。首屏刷新直接稳定呈现，文档间主动导航才播放路由动效。

### 8.2 参数表与现状差异

**代码风险，不能进入标准：** 目前手机 `before-swap` 里延时再次调用swap，会在当前Astro自动交换后第二次消费文档；本机Chrome进入详情和返回均出现 `null`。规范要求单次原子交换，把异步等待放在框架支持的准备流程；不能保留错误行为来追求遮罩时长。

### 8.3 打断与减少动效

**规范建议。** 滚轮、触摸、键盘或新的目录点击可以取消程序滚动；下一目标从当前画面继续，不先强制回原点。连续路由点击不堆积遮罩；最后一次有效导航完成后只保留一个页面、一个滚动驱动及一个当前项。

**已确认：减少动效直切。** `prefers-reduced-motion: reduce` 时不飞入、掀纸、模糊、滚动补间和逐行显影；内容立即可见，目录定位即时完成，仍更新进度与当前项。建议同时停用Lenis平滑插值，保留原生滚动与可访问控件；运行中偏好改变也应生效。

### 8.4 性能与可靠性

**规范建议。** 进度和目录读写合并到单一rAF，先读布局后写状态；标题坐标在字体/图片/尺寸变化后重算，不每次scroll先重写HTML再逐项读rect。块字符进度只在格数或显示百分比变化时更新。初始正文通过Astro输出，动效脚本失效不隐藏内容。

动画优先transform和opacity。模糊只限短暂纸面转场，避免在长正文持续应用filter；不使用 `transition: all`。字符进度不新增Canvas、SVG或滚动库。v2角色资源继续遵守既有不超过6MB的契约；实际总量以发布审计为准，不在本文声称最新素材预算已重测。

## 9 Blog 阅读进度与节点交互

**本节整体为规范建议与待确认方案。** 用户已要求讨论并写入规范，尚未批准某个具体控件形态或生产实现。D-147研究登记不能充当采用批准。

### 9.1 阅读页结构

桌面保留全站左导航，在文章上下文中增加文章标题、目录、进度；右侧仍是单列正文，不再增加第三条狭窄侧栏。左栏空间不足时目录区独立滚动，全站入口与返回入口保持可达。长目录不得把文章页变成多层滚动陷阱。

手机保留顶部全站导航，文章标题下提供可展开“目录”；关闭时显示当前章节与简短进度。建议不直接搬28格横条到390px屏幕，可用2px细进度线配可读百分比。是否采用顶线由包子确认，不能默认加永久悬浮条遮住正文。

```text
桌面
┌ 全站入口 ┐  ┌ 暖纸阅读面 ─────────────────┐
│ 返回文章 │  │ 返回文章  标题  日期与标签    │
│ 当前篇名 │  │ 正文 H2 / H3                │
│ 章节目录 │  │ 图片  引用  代码             │
│ 阅读进度 │  │ 前一篇  返回文章  后一篇      │
└──────────┘  └─────────────────────────────┘

手机
品牌与四入口 → 标题与元信息 → 目录折叠项 → 正文 → 前后篇
```

### 9.2 进度口径

**参考事实：** D-147研究使用28格文本进度，正文末尾到达视口底部即100%，不把评论/页脚当成正文。研究中的公式以页面顶部为起点，并非严格从正文首行起算；本版不把这个细节隐藏掉。

**推荐口径 A：正文区间。** 标题和摘要不计入正文长度；正文首行到达阅读线时0%，正文末尾到达可见视口底边时100%。评论、前后篇、页脚不进入分母；之后保持100%。阅读进度可倒退，不把它表述为记忆或阅读完成记录。

实现约定：设正文文档坐标顶部为S、底部为E，视口高H，顶部安全偏移O，滚动位置y；`start=max(0,S-O)`，`end=max(start,E-H)`。若end大于start，则 `p=clamp((y-start)/(end-start),0,1)`；短文可见区域已覆盖完整正文时置100%，尚未到正文时保持0%。正文尺寸变化后重算端点，不能出现NaN或超过100%。

**备选 B：完全沿用研究的页面顶部起算。** 更贴近原站，但长标题会占用一部分阅读百分比。A/B待包子确认，建议A，因为进度名称是“正文阅读进度”。

桌面建议28格纯文本与百分比；图形字符设为装饰，另外提供可访问的0–100数值。普通滚动时不逐百分点播报；不使用每帧 `innerHTML` 重建。没有JS时不显示一个永远停在0%的假进度。

### 9.3 目录与当前节点

目录从实际正文H2/H3生成，保持稳定、唯一的标题id；重复标题也必须可分享。H4是否纳入默认为否，避免目录过密；无章节文章隐藏目录，不生成虚构节点。

建议使用D-147的40%视口阅读线：当前项为最后一个越过该线的标题；处于首节前时选第一节，正文末尾选最后一节。父章节与子章节关系明确，只展开当前父组，用户也可手动展开其他组。展开控件与跳转链接分开，`aria-expanded` 用在展开按钮上；当前链接用 `aria-current` 表达。

篇名在主H1离开视口后进入左栏。建议预留一段固定空间或采用不会反复挤动目录的布局，不照搬参考页的高度动画。长标题最多两行省略时必须仍可访问完整标题。

### 9.4 节点定位与节点翻页分别定义

| 用户操作 | 推荐行为 | 路由与历史 |
|---|---|---|
| 自然滚动读到下一节 | 更新当前项与进度，不重播显影 | 不改历史，不强制吸附 |
| 点击目录节点 | Lenis定位到标题下方安全位置；标题/首段轻显影一次 | 同篇hash变化，记录一次用户导航 |
| 点击“上一节/下一节” | 如采用，等价于点击相邻H2，保留同一文档 | 不加载新文章；不能写成“上一篇/下一篇” |
| 点击底部前后篇 | 打开真实相邻文章，沿用路由纸张转场 | 改pathname；前后篇顺序沿用已批准列表规则 |
| 浏览器返回/前进 | 恢复对应路由或章节及合理滚动位置 | 响应popstate，不只改URL |

**推荐节点方案：定位加局部显影。** 它接续D-147的定位与D-142的lab显影，不把长文拆成多个页面。整张纸面按章节翻走是不同方案，会影响搜索、深链接、历史与无JS阅读，本版不推荐默认为它，也未获批准。

**待确认：是否需要独立“上一节/下一节”控件。** 目录已经能直达全部节点；建议首版先保留目录跳转与底部前后篇，避免两组“前/后”混淆。若用户所指正是节点翻页按钮，再在lab以清楚的“上一节/下一节”文案评审。

目标偏移取“当前可见固定导航高度＋16px间隙”。无固定导航的桌面可用24–36px；不在所有设备硬编码36px。首次带hash访问应等布局稳定后一次校正，不能靠固定150ms定时器假定字体和图片已加载。键盘焦点与视觉落点一致；新输入能打断长滚动。

### 9.5 采用顺序

先确认参考映射、进度口径和节点动作；再按D-147新增采用决策。之后只在带真实Lenis、真实长文、真实页面壳的lab验证，不拿独立无Lenis demo证明生产可用。包子通过桌面/手机/减少动效评审后，才进入Blog详情。
