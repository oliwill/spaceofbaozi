## 0. 文档用途与优先级

本文用于统一 baozi.space 的设计与实现。视觉稿、原型、组件和页面不得各自发展出另一套语言。

发生冲突时，按以下顺序处理：

1. 本规范中的明确规则。
2. 已通过评审的最新原型及其验收记录。
3. 页面或组件的局部说明。
4. 旧设计稿、旧提示词和历史讨论。

未经确认的局部实验不得反向改写全站规则。若一项新决定需要长期保留，应先更新本规范，再进入正式页面。

## 1. 产品定义

baozi.space 是包子的个人网站：一个持续生长的公开档案、工作台和生活索引。

它收纳：

- 文章与短想法；
- 照片与相册；
- 书、电影和音乐；
- 项目与 AI 实验；
- 个人介绍、近期状态与联系方式。

它不应被理解为：

- 包子店、餐厅或商品网站；
- 依赖隐喻才能理解的互动游戏；
- 只有视觉奇观、缺少可阅读内容的作品集；
- 可以任意拖拽、缩放、迷失方向的无限画布。

### 1.1 体验目标

访客进入后，应在十秒内理解三件事：

1. 这是一个真实的人长期维护的个人空间。
2. 这个人的兴趣横跨写作、摄影、书影音和创作。
3. 网站有独特性，但内容仍然容易找到和阅读。

### 1.2 设计原则

1. **内容先于装饰**：任何胶带、印章、涂鸦都不能妨碍标题、正文和操作。
2. **有秩序的松弛**：拼贴可以错位和重叠，但必须依附网格，不做随机散落。
3. **一屏一个视觉主角**：每个视口最多一个主视觉，其余元素形成层级而非竞争。
4. **中文优先**：主体文案使用简体中文；英文只用于固定栏目名、专有名词、日期或短标签。
5. **动作讲故事**：大动效必须推动叙事；微动效只提供状态反馈。
6. **真实可维护**：图片、文字和内容条目都可独立更新，不把整页做成一张图。
7. **优雅降级**：天气、动画或图片失败时，访客仍能进入完整网站。

## 2. 信息架构

### 2.1 一级导航

全站只保留五个一级入口：

| 栏目 | 内容范围 | 推荐路由 |
| --- | --- | --- |
| Blog | 长文章与 Thoughts 短想法 | /blog |
| Photos | 相册与摄影主题 | /photos |
| Shelf | Books / Movies / Music | /shelf |
| Projects | 项目、工具与 AI Works | /projects |
| About | 个人介绍、Now、联系信息 | /about |

Thoughts 归入 Blog，AI Works 归入 Projects。Devices、Apps、Drinks 可以作为文章、项目或 Shelf 条目的标签存在，但不进入一级导航。

### 2.2 路由基线

| 路由 | 用途 |
| --- | --- |
| / | 首页精选与入口 |
| /blog | Blog 总览 |
| /blog/thoughts | 短想法流 |
| /blog/[slug] | 文章详情 |
| /photos | 相册总览 |
| /photos/[slug] | 相册详情 |
| /shelf | Shelf 总览及类型筛选 |
| /shelf/[type]/[slug] | 单条书影音记录，可按内容需要启用 |
| /projects | 项目总览 |
| /projects/[slug] | 项目详情 |
| /about | About 与 Now |
| /lab/intro | 桌面端开场动效实验页，不进入正式导航 |

### 2.3 首页精选数量

首页是编辑过的连续展览，不是全部内容的缩略列表。

| 分区 | 首页展示量 |
| --- | --- |
| Blog | 1 篇主文章 + 3 篇近期文章 + 少量 Thoughts |
| Photos | 1 个主相册 + 2 至 3 个小相册 |
| Shelf | Books、Movies、Music 各 1 至 2 条 |
| Projects | 1 个进行中项目 + 2 个近期项目 |
| About | 简介、Now、联系方式与少量个人物件 |

首页条目必须可以进入对应的总览或详情页。不得在首页复制完整正文。

## 3. 全站体验骨架

### 3.1 无限点阵环境与暖白大纸

所有页面共享同一张没有物理边缘的低对比点阵环境。滚动时背景连续，不出现书脊、翻页、画布边框或桌面容器。真正的内容排在铺于环境上的暖白大纸中，而不是全部直接印在点阵上。

基准参数：

| Token | 值 | 用途 |
| --- | --- | --- |
| --grid-paper | #EEF0EA | 无限环境底色 |
| --dot | rgba(63, 78, 82, 0.14) | 环境点阵 |
| --content-paper | #FFFDF7 | 主要大内容纸、角色白边 |
| --paper-note | #F2EEE3 | Now、引用和小纸签 |
| 点阵间距 | 桌面 22–24px；移动端 18px | 背景重复尺寸 |
| 点阵直径 | 1px | 不抢正文对比度 |

点阵原点全站固定，不得因模块或大纸切换而重置。页面中心和大纸附近可通过极浅遮罩将点阵减淡约 20%–30%，外侧留白略清楚；减淡不得形成聚光灯、白色光晕或明显矩形。

暖白大纸规则：

- 桌面宽度为视口的 86%–90%，最大约 1360px；
- 内部继续使用 12 列编辑网格；
- 相邻章节纸面允许重叠 12–32px；
- 多数纸面保持端正，旋转不超过 ±0.3°；
- 阴影统一为 `0 8px 30px rgba(46, 48, 42, 0.08)`；
- 纸边只保留极轻纤维感，不使用明显撕边、发黄或复古磨损。

“无限”只描述环境延伸，不代表可自由拖拽或缩放的无限画布。

### 3.2 顶部导航

桌面端顶部区域由两部分组成：

- 左侧：访问者当地天气；
- 右侧：从暖白大纸上缘微微露出的 Blog / Photos / Shelf / Projects / About 白纸索引标签。

规则：

- 首页左上角不显示 baozi.space 字标。
- 网站名称保留在浏览器标题、元数据和页尾。
- 导航标签高约 34–38px，从大纸上缘露出 12–16px，上方两角圆角约 4px。
- 标签基本色与大纸接近，不使用五种不同颜色。
- 当前栏目只选择一种主状态：淡靛蓝纸色或朱红短线。
- hover 时标签上移约 2px，不旋转。
- 导航与正文保持同一内容网格，不贴浏览器边缘。
- 顶部区域可 sticky，但不得使用厚重导航条或玻璃拟态。
- 背景内容经过导航下方时，可增加轻微纸色遮罩和 backdrop blur；不使用玻璃拟态高光。
- 启动动画开始时导航不可见；人物进入首页并开始站起时逐渐出现。
- 移动端优先保持五项单行横向滚动，不把它们变成纵向卡片。

天气组件不是进入网站的前置条件：

- 正式站优先使用粗粒度 IP 城市推断，不在首次访问时索取精确 GPS 权限。
- 实验页使用固定测试数据。
- 请求失败时显示访问者本地时间或一句简短问候。
- 不显示精确位置，不储存位置历史。

### 3.3 页尾

页尾是全站最安静的区域，包含：

- baozi.space；
- 当前年份；
- RSS（上线后）；
- 联系方式或主要社交链接；
- 一句短签名。

页尾不重复完整导航，不做大面积品牌海报。

## 4. 视觉系统

### 4.1 风格定义

统一描述：

> 在一张被轻微减淡的无限点阵纸上，铺放几张暖白大纸来整理文字和照片；包子与小狗则像带白边的水彩剪纸，在纸面上完成一段短小的定格动画，然后安静地留在首页。

视觉组成建议为：

- 60% 清晰 HTML 排版与留白；
- 20% 真实照片和封面；
- 12% 纸张层级与轻拼贴；
- 8% 水彩角色与手绘元素。

网站主体保持安静的编辑排版；水彩只用于人物、小狗、黄色球、启动页草地和极少量角色边注。真实照片不转换为水彩，栏目不建立水彩图标系统。

不使用“复古”作为堆砌效果的理由。纸张颗粒、阴影和磨损必须轻微，整体仍然现代、清爽，不能滑向儿童绘本或素材情绪板。

### 4.2 色彩

| Token | 色值 | 角色 |
| --- | --- | --- |
| --grid-paper | #EEF0EA | 无限点阵环境 |
| --content-paper | #FFFDF7 | 大内容纸、角色白边 |
| --ink | #25231F | 正文、主标题 |
| --ink-soft | #67635B | 摘要、次级信息 |
| --line | rgba(37, 35, 31, 0.22) | 分隔线、描边 |
| --indigo | #284D5B | 主强调、链接、人物夏季帽子 |
| --vermilion | #B8513D | 重要状态、印章、冬季卫衣 |
| --mustard | #D7AA3F | 球、提示、冬季包 |
| --grass | #839260 | 开场草地主色 |
| --grass-deep | #69784F | 草地深部颗粒 |
| --grass-wash | #A8B486 | 草地浅色水痕 |
| --cyan | #3E91A8 | 狗项圈、轻量交互提示 |

使用限制：

- 一个视口内通常只出现一个主强调色和一个辅助强调色。
- 朱红、芥末黄、草绿和青色不得同时作为大面积色块出现。
- 正文始终使用 --ink 或满足可访问性对比度的深色。
- 状态含义不能只靠颜色表达，必须同时使用文字或图形。

### 4.3 字体

| 层级 | 字体建议 | 字重与用途 |
| --- | --- | --- |
| 中文标题 | Source Han Serif SC / 系统宋体回退 | 500 / 600；H1、H2、文章标题、引语 |
| 正文与 UI | 系统无衬线字体栈 | 400 / 500 / 600；正文、导航、按钮、标签与元数据 |
| 手写 | 定制 SVG 或图片素材 | 站点签名和极少量边注；不作为 Web Font 正文 |

规则：

- 不再加载独立等宽字体；日期和数字通过 `font-variant-numeric: tabular-nums` 对齐。
- 生产站只自托管标题实际使用的思源宋体简体中文 WOFF2 子集；正文不加载完整思源黑体。
- 正文不使用手写体和全大写英文。
- 英文字体必须与中文字体的视觉高度接近，避免中英文跳动。
- 字体加载失败时，版式仍应稳定，避免依赖特殊字形宽度完成对齐。

### 4.4 字号与行距

| 样式 | 桌面 | 移动端 | 行高 |
| --- | --- | --- | --- |
| 首页主标题 | 52–60px | 38–44px | 1.15 |
| 文章 H1 | 44–52px | 34–40px | 1.2 |
| 分区 H2 | 30–36px | 26–30px | 1.3 |
| 卡片 H3 | 21–25px | 19–22px | 1.4 |
| Body | 17–18px | 16–17px | 1.75–1.85 |
| Navigation | 14–15px | 14px | 1 |
| Meta / Tag | 12–13px | 12px | 1.4 |

正文每行建议 34 至 42 个中文字符，文章详情最大文本宽度约 720px。

### 4.5 网格与间距

桌面基准画布为 1440 × 900，首屏按 16:9 验证，同时兼容 1280 × 720。

| 项目 | 桌面规则 |
| --- | --- |
| 大内容纸最大宽度 | 1360px |
| 页面左右安全边距 | clamp(32px, 5vw, 80px) |
| 主网格 | 12 列 |
| 列间距 | 24px |
| 顶部导航参考高度 | 64–72px |
| 基础间距单位 | 4px |
| 常用间距 | 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128px |

所有不对称布局都从主网格出发。元素可以跨列或局部越界，但其锚点必须落在列线或基础间距上。

### 4.6 线、圆角与阴影

- 分隔线：1px，使用 --line。
- 大内容纸圆角：0–2px；普通相纸可为 2px。
- 索引导航只在上方两角使用约 4px 圆角。
- 纸片按钮圆角约 5px；不使用胶囊按钮。
- 大内容纸阴影：`0 8px 30px rgba(46, 48, 42, 0.08)`。
- 图片阴影：`0 8px 24px rgba(37, 35, 31, 0.10)`。
- 水彩剪纸角色阴影：`0 3px 8px rgba(37, 35, 31, 0.12)`。
- 同一页面共享左上方光源，所有投影向右下；角色最近、照片稍宽、大纸最柔和。
- 不使用霓虹、强发光、多层彩色阴影、立体倒角或厚重拟物投影。

## 5. 拼贴语法

### 5.1 五层模型

每个页面固定使用五类层：

1. **环境层**：无限低对比点阵与极轻纸张颗粒。
2. **页面层**：暖白大内容纸。
3. **内容层**：HTML 文字、真实照片、封面、链接和数据。
4. **角色层**：水彩人物、小狗、黄色球、草地与极少量角色边注。
5. **材料层**：相纸、小纸签、胶带、印章和手写素材。

材料层与角色层永远服务内容层，不能遮挡正文、焦点轮廓、按钮、人物面部或小狗关键轮廓。

### 5.2 密度限制

- 每个视口最多一个主视觉。
- 每个视口最多一个明显打破网格的元素。
- 一个视口通常只出现一张主纸、至多两张照片纸和一处小纸签。
- 单个局部堆叠最多三层。
- 同一视口胶带不超过一处，印章不超过一处，涂鸦或手写边注不超过两处。
- 正文、导航和按钮不旋转。
- 主照片旋转不超过 ±1°；小照片不超过 ±1.5°；纯装饰最多 ±3°。
- 重叠面积通常不超过被覆盖内容面积的 12%，且不得覆盖语义关键信息。
- 不为每条内容建立独立悬浮纸卡；正文和列表直接排在大纸上。

### 5.3 图片处理

- 优先使用真实照片，不统一套滤镜。
- 允许轻微降低饱和度或对比度，使不同来源的图片能够共处。
- 真实照片不得转换为水彩；水彩只属于角色和少量手绘元素。
- 主图保持自然比例；不得为了拼贴强行裁掉人物、动物或物件的识别特征。
- 拍立得白边和相纸边框应做成可复用组件，不在每张图中重复烘焙；相纸边缘比角色剪纸边更规则、更窄。
- 不为每张照片重复添加胶带、图钉或撕纸效果。
- 图片中的文字不承担核心信息；标题和说明必须是可选择、可缩放的 HTML 文本。

### 5.4 水彩剪纸规则

- 共同画法为深灰细墨线、低饱和透明水彩、少量水痕和纸张颗粒。
- 人物白边为最长边的 2.5%–3%；小狗 3%–4%；黄色球 3%。
- 白边使用 `--content-paper`，边缘轻微不均匀但保持干净。
- 不做纯白粗描边、大头吉祥物、通用日漫脸、3D 高光或扁平矢量图标。
- 水彩剪纸只用于启动人物、小狗、球、草地、首页最终状态，以及 About、404、页尾的极少量角色延续。
- Blog、Photos、Shelf 和 Projects 不建立水彩图标系统。

### 5.5 常用组件语言

| 组件 | 视觉职责 |
| --- | --- |
| WeatherLabel | 低调显示天气或本地时间 |
| GlobalNav | 五个白纸索引一级入口 |
| IdentityBlock | 水彩剪纸人物、小狗与四行身份文字 |
| ContentSheet | 承载一个大章节的暖白大纸 |
| FeatureStory | 一篇主文章或一个主项目 |
| PhotoStack | 2 至 3 张照片的受控叠放 |
| MetaStrip | 日期、标签、状态、阅读时长 |
| MarginNote | 短边注；不承载必读内容 |
| SectionIndex | 栏目编号与总览入口 |
| TextLink | 默认内容操作；下划线与箭头反馈 |
| PaperButton | 联系、下载、返回和跳过等明确操作 |

### 5.6 按钮与标签

- 默认操作使用文字链接；hover 时下划线延长，箭头向右移动约 3px。
- 纸片按钮使用暖白背景、1px 墨灰边框、5px 圆角和轻投影，仅用于明确操作。
- 图标按钮只用于灯箱关闭与翻页等标准操作，点击区域至少 40×40px。
- 所有交互的 focus-visible 使用 `2px solid #284D5B`，偏移 3px。
- 内容标签为 12–13px 墨灰文字、浅细边框、3–4px 圆角；每条内容最多三个，不强制 `#`。
- 栏目筛选使用小型纸张索引，选中态为淡靛蓝底色并提供非颜色提示。
- 项目状态固定为 idea · 构想中、building · 制作中、shipped · 已完成、archived · 已归档。
- 标签不旋转、不随机着色，也不能与可交互筛选器具有完全相同的外观。

组件之间共享颜色、字体、阴影和动效 token，不为单页重新发明样式。

## 6. 页面设计规范

### 6.1 页面拼贴密度

下表中的“拼贴触感”指材料层与自由排版的占比，不是内容数量。

| 页面 | 编辑秩序 | 拼贴触感 |
| --- | ---: | ---: |
| 首页 | 65% | 35% |
| Blog 总览 | 75% | 25% |
| Blog 详情 | 90% | 10% |
| Photos | 50% | 50% |
| Shelf | 70% | 30% |
| Projects | 70% | 30% |
| About | 65% | 35% |

总览页允许更多节奏变化；详情页优先阅读，拼贴主要出现在页首、图注和段落间歇。

### 6.2 首页首屏（Home v2）

Home v2 是启动页动画完成、跳过、会话完成、`prefers-reduced-motion` 与素材失败等所有路径共同落入的唯一首页状态。首屏建议最小高度 100svh；桌面基准 1440×900（兼容 1280×720 与 1920×1080），移动端基准 390×844。首屏内容位于一张视口宽度 86%–90% 的暖白大纸上；点阵环境从四周露出，建立清楚纸张边界。

#### 桌面静态首屏（1440×900）

- **顶部**：左侧为访问者天气或失败回退信息，位于环境或大纸安全区内；右侧为从大纸上缘露出的 Blog / Photos / Shelf / Projects / About 五项白纸索引导航。不放网站名称、Logo 大图或社交图标组。
- **左侧中文信息区（约 4–5 列）**：四行文字依次为当前时段问候、称呼、所在城市、一句介绍（记录写作、照片、书影音与正在做的事）。四行按信息层级排版，不做四个相同大小的口号。
- **右侧人物与嘉乐区（约 6–7 列）**：人物站姿与嘉乐初始位置使用与启动页末帧相同的 `handoff-final` 构图；两者共用同一地面线，保持水彩剪纸白边，可略微越过大纸边缘。该区域是后续实时互动的唯一挂载点；静态基线只呈现批准的定帧，不加载互动资产。
- **底部 Blog 露出**：首屏下缘只露出 Blog 分区约 8%–12% 的内容（栏目标题或主图边缘），负责提示继续滚动，不与人物区争夺注意力。

#### 移动端静态首屏（390×844）

- **顶部**：天气 / 回退信息加五项索引导航单行横向滚动，不收进汉堡菜单。
- **信息区与角色区纵向排列，不得互相遮挡**：中文信息区在上，人物与嘉乐区在下；角色区整体高度不超过首屏约 40%，人物与嘉乐共用同一地面线，按 9:16 构图重新排布，不直接等比缩放桌面构图。
- **底部**：同样只露出 Blog 分区约 8%–12%。

#### 桌面 / 移动静态首屏对照

| 项目 | 桌面 1440×900 | 移动 390×844 |
| --- | --- | --- |
| 首屏高度 | 100svh，16:9 基准，兼容 1280×720 / 1920×1080 | 100svh，9:16 基准 |
| 大纸宽度 | 视口 86%–90%，最大约 1360px | 两侧各留 12–20px 点阵环境 |
| 网格 | 12 列 | 4 列，左右安全边距 20px |
| 信息区位置 | 左侧 4–5 列 | 上方全宽，4 列内 |
| 人物与嘉乐位置 | 右侧 6–7 列 | 信息区下方，≤ 首屏约 40%，不与文字重叠 |
| 导航 | 大纸上缘露出的五项白纸索引标签 | 五项单行横向滚动 |
| 底部露出 | Blog 分区 8%–12% | Blog 分区 8%–12% |
| 角色静态状态 | `handoff-final` 桌面定帧 | `handoff-final` 移动定帧（构图可重排，角色身份不变） |

#### 无动画静态状态与动效占位边界

- 无 JavaScript、`prefers-reduced-motion`、素材失败、跳过和会话完成路径都直接渲染本节描述的静态首屏；文案、导航和链接全部是真实 DOM，不烘焙进视频或图片。
- 互动资产加载失败时保持 `handoff-final` 定帧，不阻塞首页内容；静止后停止动画循环和持续几何读取。
- 启动页末帧与 Home v2 第一帧使用同一张批准的 `handoff-final` 基准图；人物脚底、身体尺度、嘉乐位置、点阵原点、纸张色温和裁切方式两端一致，不允许交接时角色缩放、平移、换衣服、换姿势或改变描边。
- `/lab/intro` 与 `/` 后续共用同一个 Home v2 组件，不再复制一套占位首页。

CP0 人工评审使用隔离路由 `/lab/home-v2`。该路由必须以同一个语义组件响应式呈现 1440×900 与 390×844 两种构图，不能维护两套页面；允许临时复用已审计的透明角色帧验证比例，但必须明确标注为构图占位，不得把临时姿态视为批准的 `handoff-final`。评审截图存放在 `design-assets/home-v2/review/`，不发布到 `public/`。

CP0 评审后的角色区域位置与尺寸冻结：桌面为 Hero 右侧 6–7 列，移动为信息区下方且不超过首屏约 40%；人物与嘉乐共用地面线和当前角色关系。CP1 只调整具体动作姿态或批准的姿态帧，不得改变本构图区域、位置、尺寸或两角色相对关系。



### 6.3 首页后续分区

首页按以下顺序组织：

1. Home v2 首屏（中文信息 + 人物与嘉乐定帧）；
2. Blog（首屏后第一内容区，含主文章与近期文章）；
3. Photos；
4. Shelf；
5. Projects；
6. About；
7. Footer。

每个分区使用不同的网格组合，但保持同一环境点阵、纸张光源和阅读方向。大章节可以使用下一张暖白大纸，并与前一张重叠 12–32px；不要给每个分区添加独立满幅色块，也不要为每条内容创建卡片墙。

### 6.4 Blog 总览

- 首位使用一篇主文章。
- 其余文章以 2 列或不等宽列表排列。
- Thoughts 作为更轻、更密的文字流出现，和长文章有明确视觉差异。
- 分类、年份和标签使用文本筛选，不使用复杂仪表盘式控件。
- 每张卡片至少包含标题、日期、摘要或类型信息。

### 6.5 Blog 详情

- 页首可有一处拼贴式封面与 MetaStrip。
- 正文保持单列，最大宽度约 720px。
- 大图可适度跨出正文列；图注仍对齐正文或图像边缘。
- H2、引用、代码、脚注和分隔符使用统一文章样式。
- 正文末尾提供返回 Blog、上一篇/下一篇或相关内容，不使用无限推荐流。

### 6.6 Photos

- 总览以相册为单位，不直接铺满所有单张照片。
- 主相册可使用较强的 PhotoStack；次级相册保持规则缩略图。
- 相册详情以照片节奏为主，允许横竖图交替、满宽图和短文字段落。
- 查看大图时支持键盘关闭、焦点管理和触摸手势；关闭后返回原图位置。

### 6.7 Shelf

- Books、Movies、Music 使用同一视觉骨架，但保留各自字段。
- 封面或唱片图像不得被过度裁切。
- 条目可显示年份、作者/导演/艺人、状态和一句短评。
- Shelf 首页通过清楚的类型筛选切换，不为三种内容建立三套互不相干的卡片。

### 6.8 Projects

- 首位固定展示一个进行中项目。
- 状态统一为 idea / building / shipped / archived，并提供中文解释。
- AI Works 是项目类型或筛选项，不作为一级导航。
- 项目详情按“问题—过程—结果—反思”组织，过程图可以使用较高拼贴密度。

### 6.9 About

- 包含个人简介、Now、关注主题、联系方式和少量个人物件。
- 水彩剪纸人物和小狗可再次出现，但不重复首页完整开场；404 与页尾也只允许极少量延续。
- Now 必须有更新时间。
- 避免传统简历模板；经历信息可作为简洁时间线或文字列表。

## 7. 开场动效规范

开场用一个短小、幽默的连续动作介绍“我”和小狗，并自然把访客带入首页。它是一段可跳过的叙事，不是网站加载器，也不是进入内容的障碍。

本章 §7.2–§7.6 记录 D-115 的 A1 滚动 Sprite 实验，只作为动作参考，不再定义生产开场方向。

生产开场自 D-121 起改用 oil-motion 帧映射方案：背景（点阵纸、暖白大纸、草地）由网页静态层提供；Seedance 2.5 只在纯色键背景上生成角色语义动作（嘉乐朝右原地奔跑、人物被向右拉拽—失衡—向右摔倒）；滚动驱动单一进度，映射到 alpha-atlas + DOM/CSS Sprite；程序控制横向位移、尺度、球旋转、退出边界与 SVG 牵引绳。嘉乐先、人物后均从屏幕右侧退出，角色完全离屏后以暖白纸遮罩无缝交接 Home v2。WebGL / Canvas 为停止条件，本轮不启用。分镜、关键帧与共同定帧合同见 `docs/animation/oil-motion/` 与根目录《baozi.space 启动页 Oil Motion 项目管理计划》。

现有 A1 舞台上方保持低对比点阵，下方 22%–26% 为灰调橄榄绿水彩草地；除“跳过动画”外，不显示导航、标题或欢迎文案。

现有 `/lab/intro` 继续作为桌面动作参考，不再扩展为生产实现；生产开场自 D-121 起按 oil-motion 计划的 CP1–CP7 逐阶段放行，不再消费旧 hybrid 的 CP1 冻结输入作为生产合同。

### 7.2 方向规则

全段采用统一屏幕动线：

- 球、狗和人物均从屏幕左侧进入，向右运动；
- 草地场景中的人物从屏幕右侧摔出；
- 切换到首页后，人物从屏幕左侧摔入；
- 不朝镜头跑，不撞摄像机，不制造视角方向突变；
- 回滚时允许时间线反向播放，但人物朝向不因回滚而翻转。

### 7.3 八个关键镜头

| 镜头 | 画面 | 必须满足 |
| ---: | --- | --- |
| 1 | 黄色小球单独滚入 | 第一拍只有球，没有狗 |
| 2 | 白色小狗从左进入追球 | 狗始终朝右，项圈为青色 |
| 3 | 牵引绳绷紧，把人物拉入 | 人物为夏季造型，受力方向清楚 |
| 4 | 人与狗一起向右跑 | 保持侧视，速度逐步提高 |
| 5 | 人物接近右侧失去平衡 | 先有踉跄，再有摔倒 |
| 6 | 人物从右侧摔出 | 草地点阵在此形成匹配转场 |
| 7 | 人物从首页左侧摔入并落地 | 新场景坐标重置不可被看见 |
| 8 | 人物站入身份区，小狗绕一圈停下 | 站稳后整理帽子或衣服，身份文字出现 |

人物、小狗和球均使用暖白描边水彩剪纸。角色姿态以约 8–10 fps 切换，空间位移保持连续；每次换帧可保留 1–2px 上下差异和不超过 ±0.5° 的轻微旋转。

### 7.4 桌面滚动映射

实验页总滚动高度约 300vh，舞台 sticky 100svh。以下为初始映射，可在不改变叙事顺序的前提下微调：

| 滚动进度 | 动作 |
| --- | --- |
| 0%–8% | 球单独滚入与轻微弹跳 |
| 8%–25% | 狗进入并追球 |
| 25%–45% | 牵引绳绷紧，人物被拉入 |
| 45%–65% | 人与狗共同奔跑 |
| 65%–78% | 人物踉跄、失衡 |
| 78%–82% | 从草地场景右侧摔出，完成场景切换 |
| 82%–90% | 从首页左侧落地并站起，进入左侧身份区 |
| 90%–100% | 狗绕人物半圈并停下，身份内容稳定显示 |

### 7.5 场景转场

- 启动页与首页共享同一低对比无限点阵环境，不建立独立天空。
- 草地占视口下方 22%–26%，由 `--grass` 稳定色块、不规则水彩上缘和极少量细草构成；上缘高度变化不超过视口高度的 2%–3%。
- 点阵可极轻微透过水彩草地，但不能像简单的半透明绿色滤镜。
- 转场以人物出画、草地收回和暖白大纸进入完成，不使用闪白、黑场、翻页或镜头撞击。
- 78%–82% 区间内完成坐标重置；任何单帧都不能同时看到两个人物副本。
- 人物从首页左侧进入时可略微越过大纸左边缘，白边和投影在两个场景中保持一致。
- 暖白大纸从 78% 开始以轻微上移和淡入进入，和草地退出重叠；不得在两者之间留下空舞台。
- 首屏 Blog 内容可在人物站起前保持低对比或轻微错位，最终状态才完全清晰。

### 7.6 播放行为

- 首次会话默认播放；完成后写入 sessionStorage，仅对当前会话生效。
- 提供清楚但低调的“跳过动画”。
- 用户主动回滚时，实验页时间线可逆。
- 正式首页完成一次后，重新进入同一会话直接显示最终状态。
- prefers-reduced-motion: reduce 下不播放奔跑和摔倒，直接呈现人物站立、小狗停下的最终状态。
- 素材或脚本加载失败时直接进入首页，不显示空舞台。
- 动画结束后人物和小狗完全静止，不保留呼吸、漂浮、眨眼或摇摆循环。

## 8. 人物与小狗设定

### 8.1 人物识别特征

- 身形：纤瘦，约 177cm 的视觉比例；
- 面部：东亚男性，圆框眼镜；
- 头发：黑色，中长至肩附近；
- 识别点：额头痣；
- 气质：自然、稍带运动感，不做夸张英雄比例。

插画是对真人特征的提炼，不追求照片级写实。侧视奔跑时仍需保留圆框眼镜、发长和帽型三个高识别特征。共同画法为深灰细墨线、低饱和透明水彩、轻微越线、水痕和纸张颗粒，不得转成通用日漫人物。

### 8.2 夏季造型：默认与 MVP

| 部位 | 规范 |
| --- | --- |
| 帽子 | 深靛蓝渔夫帽 |
| 眼镜 | 细圆框 |
| 上衣 | 暖白短袖纽扣衬衫，带深蓝复古相机线稿印花 |
| 下装 | 深海军蓝及膝短裤 |
| 鞋 | 深蓝低帮便鞋，浅色中底 |
| 手表 | 白色运动手表 |
| 禁止附加 | 背包、托特包、卫衣、长裤 |

开场动画、首页最终站立状态和第一阶段人物素材全部使用此造型。

### 8.3 冬季造型：后续季节版本

| 部位 | 规范 |
| --- | --- |
| 帽子 | 蓝色尖顶针织帽 |
| 内层 | 砖红或暗红色卫衣 |
| 外套 | 暖白色宽松外套，带明显贴袋 |
| 包 | 亮黄色托特包 |
| 下装 | 深蓝色长裤 |
| 鞋 | 灰色跑鞋 |

冬季造型当前只用于角色设定表，不进入第一阶段开场 Sprite。未来若制作季节切换，必须整套替换，不能把冬季单品混入夏季造型。

### 8.4 小狗设定

- 体型：约 5kg 的小型犬，身体轻巧；
- 毛色：柔软白色；
- 耳朵：下垂；
- 口鼻：略长于圆脸玩具犬，黑色鼻头；
- 眼睛：深色、小而清楚；
- 项圈：青色；
- 动作气质：专注追球、轻快、略有笨拙感。

小狗不能被画成大头吉祥物，也不能在不同动作组中改变犬种特征和体长比例。

人物、小狗和球统一增加暖白剪纸边：人物为最长边的 2.5%–3%，小狗为 3%–4%，黄色球为 3%。小狗白边稍厚，以保证白毛在大纸和点阵环境上都清楚。白边轻微不均匀但必须干净，不得做成粗大表情包描边。

### 8.5 动画素材清单

第一阶段至少需要：

| 素材 | 帧数 | 用途 |
| --- | ---: | --- |
| Ball Roll / Squash | 8 | 滚动、弹跳与变形 |
| Dog Run | 8 | 从左向右追球 |
| Dog Circle / Settle | 8 | 首页绕人物与停下 |
| Person Pulled / Run | 8 | 被牵引并进入奔跑 |
| Person Trip / Exit | 8 | 失衡、摔倒并离开右侧 |
| Person Land / Stand | 8 | 从左落地、站起、整理帽子或衣服 |

牵引绳使用动态 SVG 三次贝塞尔曲线绘制，不作为位图烘焙在人物或狗的帧中。绳子两端锚点随当前帧更新，并允许在少量手绘感线形间切换，以匹配定格动画；不得脱离人物手端和小狗项圈端。

### 8.6 Sprite 生产规则

生成图或角色设定表不是可直接上线的 Sprite Sheet。进入代码前必须完成：

1. 清除棋盘格或伪透明背景，确认真实 Alpha 通道。
2. 按本节比例增加暖白不规则剪纸边，并验证白毛、暖白衬衫、手指、帽檐和眼镜没有被抠图破坏。
3. 将每组动作精确切为 4 × 2 的等尺寸帧。
4. 统一人物和小狗在所有动作组中的画布尺寸、比例、地面基线与朝向。
5. 修复多余肢体、服装跳变、眼镜消失、帽型变化和项圈颜色漂移。
6. 保留受控定格差异：姿态切换按 8–10 fps 设计，允许 1–2px 上下位移和不超过 ±0.5° 的逐帧差异。
7. 为脚底、重心、牵引绳手端、项圈端和视觉中心记录锚点。
8. 重新打包为带透明通道的 WebP；PNG 只作为兼容或无损源文件。
9. 输出 manifest，记录文件名、帧数、目标帧率、循环方式、画布、白边比例和锚点。

所有开场 Sprite 必须朝右。不得在 CSS 中用 scaleX(-1) 临时修正错误素材，因为它会同时翻转服装细节和锚点。

### 8.7 素材命名建议

~~~text
public/assets/intro/production/
  ball/ball-bounce.webp
  dog/dog-run-right.webp
  dog/dog-circle-settle.webp
  person/summer-pulled-run-right.webp
  person/summer-trip-exit-right.webp
  person/summer-land-stand.webp
  intro-final-still.webp
  intro-manifest.json
~~~

### 8.8 双轨素材交付与责任边界

本地 harness 不承担人物、小狗、球、手写字或装饰素材的生成与重绘。图片生产与网站实现分为两条相互独立、通过固定文件契约衔接的轨道：

1. **Harness 轨道**：建立素材类型、Manifest、占位 Sprite、审计脚本、动画时间线、回退和测试。占位素材只用于验证尺寸、帧序、锚点、转场和性能，不得冒充正式视觉资产。
2. **视觉素材轨道**：在 ChatGPT 或人工图像流程中完成真实 Alpha、暖白剪纸边、逐帧修复、统一基线、锚点标注和生产 WebP。生产素材按固定文件名交付后，harness 只执行审计和替换，不重新生成图像。

六组生产 Sprite 的文件名、动作名和帧数一经锁定，不因生产工具改变：

~~~text
public/assets/intro/production/
  ball/ball-bounce.webp
  dog/dog-run-right.webp
  dog/dog-circle-settle.webp
  person/summer-pulled-run-right.webp
  person/summer-trip-exit-right.webp
  person/summer-land-stand.webp
  intro-final-still.webp
  intro-manifest.json
~~~

开发占位素材放在 `public/assets/intro/placeholders/`，生产素材放在 `public/assets/intro/production/`。默认页面始终请求生产目录；只有显式调试参数或测试环境可以选择占位目录。若生产素材缺失或加载失败，页面直接进入稳定首页状态，不自动回退到会被访客看到的彩色占位图。

Manifest 是两条轨道的唯一接口，至少记录：`id`、`src`、`frames`、`columns`、`rows`、`fps`、`loop`、单帧尺寸、显示尺寸、白边比例，以及每帧的 `ground`、`center`、人物 `hand` 或小狗 `collar` 归一化锚点。人物、小狗和球的运行时代码不得把这些数值散落在组件中。

点阵、暖白大纸、投影、纸签、牵引绳和草地主体由 CSS／SVG 实现，不需要图片生成。草地只允许使用一个轻量 SVG 水彩上缘遮罩或程序化路径，不生成整屏风景图。

## 9. 动效系统

### 9.1 动效层级

| 层级 | 时长或方式 | 示例 |
| --- | --- | --- |
| 即时反馈 | 120–180ms | 链接下划线、按钮按下 |
| 组件状态 | 220–320ms | 卡片轻抬、图片揭示 |
| 页面进入 | 400–650ms | 标题、主图分层出现 |
| 开场叙事 | 与滚动进度绑定 | 连续位移中的 8–10 fps 定格姿态 |

推荐缓动：

- UI 进入：cubic-bezier(0.22, 1, 0.36, 1)；
- UI 离开：cubic-bezier(0.4, 0, 1, 1)；
- 小球弹跳和绳索受力可使用更具弹性的自定义曲线；
- ScrollTrigger 使用轻微 scrub 平滑，不安装额外平滑滚动库。
- 人物、小狗与球的空间位移连续，Sprite 姿态离散切换；不使用运动模糊和骨骼插值。
- 动画最终状态必须完全静止，不保留装饰性循环。

### 9.2 Hover 与滚动

- 卡片 hover 位移不超过 3px，旋转变化不超过 0.5°。
- 链接必须有颜色之外的反馈，例如下划线、箭头位移或边框变化。
- 白纸索引导航 hover 上移不超过 2px，纸片按钮上移不超过 1px。
- 普通内容进入动画不应全部从同一方向飞入；以透明度和 8–16px 位移为主。
- 不给所有照片添加视差；每个大分区最多一个低幅度视差对象。
- 触摸设备不依赖 hover 才显示关键信息。

### 9.3 Reduced Motion

开启 reduced motion 时：

- 禁用开场叙事、视差、持续漂浮和弹性位移；
- 保留不超过 120ms 的颜色或透明度状态反馈；
- 所有内容直接处于稳定布局，不因禁用动画而缺失或重叠。

## 10. 响应式规则

### 10.1 桌面端：第一优先级

- 第一阶段验收尺寸：1440 × 900。
- 第二验收尺寸：1280 × 720 与 1920 × 1080。
- /lab/intro 先只实现桌面交互，但代码不得硬编码单一像素坐标；位置以舞台比例和锚点计算。

### 10.2 平板

- 采用 8 列网格。
- 大内容纸左右继续露出点阵环境，不扩展为满屏白色卡片。
- 首页中文信息区和人物与嘉乐区可保持左右结构，宽度不足时改为上下排列。
- 白纸索引导航优先保留文字；必要时允许横向滚动，不立即收进汉堡菜单。

### 10.3 移动端

移动端不是桌面拼贴的缩小版，而是重新排版：

- 使用 4 列网格，左右安全边距 20px。
- 大内容纸与视口边缘保留约 12–20px 点阵环境，纸张阴影减弱。
- 首页按天气/导航、中文信息、人物与嘉乐、Blog、Photos 的顺序垂直排列。
- 装饰层数量减半；会造成遮挡的胶带、印章和边注直接隐藏。
- 照片叠放改为轻微错位或横向滑动，不做小尺寸多层堆叠。
- 正文始终保持正常文档流。
- 移动端开场与桌面共享同一动作表与 alpha-atlas 图集，按 390×844 竖屏构图独立排布横向几何与退出边界；不再制作 200vh 滚动 Sprite 版本，也不使用 9:16 整屏预渲染视频。
- 五项索引导航保持单行横向滚动；只有经过拥挤测试后才改为折叠菜单。

断点以内容是否拥挤为依据，初始建议：

- compact：小于 768px；
- medium：768px 至 1099px；
- wide：1100px 及以上。

## 11. 内容与文案规范

### 11.1 语言

- 主体文案使用简体中文。
- Blog、Photos、Shelf、Projects、About 只作为稳定英文索引导航名。
- 页面标题和分区标题使用中文；不再同时显示同义中英双标题，例如不使用 `PHOTOS / 最近拍下`。
- 不在同一句中无意义混排中英文。
- 专有名词首次出现可保留原文，并提供必要中文说明。

### 11.2 语气

- 第一人称、具体、克制，有个人温度。
- 避免品牌广告式口号和“探索无限可能”等空泛表达。
- 边注可以幽默，但不能替代核心说明。
- 项目状态、更新时间和内容来源要诚实清楚。
- 按钮使用“阅读全文”“查看所有文章”“进入相册”等具体操作，不使用“立即探索”“发现更多”等营销式文案。

### 11.3 日期与元数据

- 中文正文日期默认写作 2026 年 8 月 13 日。
- 紧凑元数据可使用 2026.08.13。
- 项目状态使用英文 token + 中文说明，例如 building · 制作中。
- 阅读时长、标签和地点不是必填；没有信息时不显示空占位。

### 11.4 无障碍文本

- 内容图片提供描述图像意义的 alt。
- 纯装饰胶带、纹理、印章使用空 alt 或 CSS 背景。
- 相册图注与 alt 不机械重复。
- 动画跳过按钮、灯箱关闭按钮和导航均使用明确中文可访问名称。

### 12.3 动画实现边界

- ScrollTrigger 只拥有滚动进度与时间线，不直接混入内容数据逻辑。
- Sprite 播放器只负责根据进度选择帧。
- 牵引绳模块根据人物手端与狗项圈端锚点更新 SVG path，并可在少量手绘曲线预设间切换。
- 角色外层只负责连续位置和轻微旋转，内层 Sprite 只负责 8–10 fps 姿态切换，二者不得争用同一 transform。
- 无限点阵环境与暖白大纸必须是独立 DOM/CSS 层，转场时点阵原点不重置。
- 场景布局使用 CSS 和舞台比例；GSAP 主要写 transform、opacity 和必要的 CSS 变量。
- 不在滚动回调中反复读取布局并同步写入，避免 layout thrashing。
- 开发模式可显示进度、锚点和舞台安全区；生产模式必须关闭。

### 12.4 内容结构

阶段 C 的目标内容目录：

~~~text
src/content/
  blog/       # 长文章与 Thoughts 类型
  photos/     # 相册 / 摄影系列
  shelf/      # type: book | movie | music
  projects/   # 项目、工具与 AI Works
  about/      # 简介与 Now
~~~

通用治理字段至少包括：

- `title`；
- `description`；
- `date` / `updated`；
- `tags`；
- `cover` / `coverAlt` / `coverCredit`；
- `draft` / `approved`；
- `featured`；
- `type`；
- `status`（项目）；
- `externalUrl`（可选）。

Shelf 的书、电影／剧集和音乐字段使用 `type` 判别后分别校验，不能为了统一集合丢失三类内容的业务语义。

### 12.5 图片工作流

PicGo 可继续作为上传入口，但页面数据只保存稳定 HTTPS URL 与必要尺寸信息。

生产前必须确认：

- 原图和缩略图策略；
- WebP/AVIF 输出；
- 外链缓存与失败占位；
- 图片迁移后的批量替换方式；
- 相册大图的加载上限。

开场生产 Sprite 与极少量界面图形随代码发布，不走普通相册外链。生产 Sprite 必须先通过独立素材契约和审计；本地 harness 只消费、验证和编排这些资产，不承担生成或重绘。开发占位 Sprite 与生产 Sprite 使用相同 Manifest 接口，但访客默认永远不会看到占位素材。

### 12.6 性能预算

初始目标：

- 首页关键首屏资源压缩后不超过约 1.5MB，不含延迟加载内容；
- 全套桌面开场动画资源压缩后不超过约 6MB；
- 字体只加载实际使用的字重与子集；
- 正文使用系统无衬线字体，不下载完整 CJK 无衬线 Web Font；
- 首屏之外图片默认懒加载；
- 动画主要使用 transform 和 opacity；
- 低性能设备可直接进入最终状态。

性能预算是上线门槛，不以牺牲角色一致性和可读性为代价；超出时先减少帧尺寸、无效透明区域和预加载范围。

### 12.7 可访问性

- 正文和交互文字满足 WCAG AA 对比度目标。
- 全站支持键盘导航和清楚的 focus-visible。
- 标题结构按语义层级组织，不用字号伪装标题。
- 跳过动画在键盘进入页面后容易到达。
- 动画不造成快速闪烁。
- 灯箱、菜单和任何模态层正确锁定并恢复焦点。

## 13. 实现阶段

### 阶段 A0-H：Harness 素材契约与占位轨道

目标：在不生成任何正式图片的前提下，把动画代码所需的素材接口锁定，使 `/lab/intro` 可以用明显的调试占位 Sprite 开发和测试。

交付：

- 固定目录、文件名和 TypeScript Manifest 类型；
- 六组 4 × 2 调试占位 Sprite；
- Alpha、尺寸、帧数、锚点、总体积和占位泄漏审计；
- 素材失败时直接进入稳定首页的回退；
- 明确禁止 harness 生成、补画或重新设计人物与小狗。

### 阶段 A0-V：生产视觉素材轨道

目标：在 ChatGPT 或人工图像流程中把已确认动作源稿加工为生产级动画资产，并按 A0-H 契约交付。

交付：

- 夏季人物三组 8 帧 Sprite；
- 小狗跑步与原地停下两组 8 帧 Sprite；
- 小球 8 帧 Sprite；
- 一张 `intro-final-still.webp` 稳定降级图；
- 人物、小狗和球的暖白剪纸边；
- 锚点与帧信息 manifest；
- 透明背景、白边比例、基线、尺寸、朝向和白毛／浅色服装边缘检查报告。

A0-H 与 A0-V 可以并行。A1 可在 A0-H 完成后使用占位素材开发，但正式视觉验收和合并必须等待 A0-V 通过审计。

### 阶段 A1：桌面 /lab/intro 原型

目标：只验证滚动叙事、动作衔接和最终首页落点，不搭建完整网站。

验收：

- 1440 × 900 下八个关键镜头顺序正确；
- 第一拍只有球，随后才出现狗；
- 全段从左向右，不发生朝向跳变；
- 人物从草地右侧离开并从首页左侧进入；
- 人物站稳后小狗完成半圈并在脚边原地停下，不保留自主循环；
- 启动页下方 22%–26% 为水彩草地，背景点阵与首页保持同一原点；
- 姿态呈现 8–10 fps 定格感，角色空间移动保持连续；
- 首页出现暖白大纸，角色可略微越过大纸左边缘；
- 回滚、跳过、reduced motion 和素材失败回退可用；
- 动画结束位置与首页身份区构图一致。

### 阶段 B：首页整合

目标：把原型最终状态接入真实首页首屏。

交付：

- 天气与导航；
- 低对比无限点阵环境与暖白首屏大纸；
- 白纸索引导航；
- 人物身份四行文字；
- Blog 主文章；
- Photos 底部预告；
- 会话播放状态；
- 首屏性能与可访问性验证。

### 阶段 C：全站页面系统

按 Blog、Photos、Shelf、Projects、About 的顺序建立总览和详情模板，并接入真实内容集合。

### 阶段 D：移动端与季节扩展

完成移动端简化开场、完整响应式检查；如有需要，再制作冬季人物整套 Sprite。冬季素材不得阻塞桌面夏季 MVP。

## 14. 质量验收清单

### 14.1 视觉一致性

- [ ] 所有页面使用同一低对比无限点阵环境和同一网格原点。
- [ ] 大章节使用暖白大纸，而不是大量独立悬浮卡片。
- [ ] 字体只使用思源宋体标题、系统无衬线正文与极少量定制手写素材。
- [ ] 每屏只有一个主视觉和最多一个网格破界元素。
- [ ] 装饰不覆盖文字、操作、人物脸部或小狗关键轮廓。
- [ ] 颜色来自统一 token，没有临时新增高饱和色。
- [ ] 长文页面的拼贴密度明显低于 Photos 和首页。
- [ ] 真实照片保持摄影材质，没有被统一水彩化。
- [ ] 导航为白纸索引标签，不是五张彩色便利贴。

### 14.2 开场叙事

- [ ] 球先出现，狗后出现，人物最后被牵入。
- [ ] 球、狗、人物始终遵守左进右出的主方向。
- [ ] 没有撞屏幕或朝镜头奔跑。
- [ ] 草地与首页切换无黑场、闪白和人物重影。
- [ ] 草地高度保持在视口 22%–26%，不构成完整风景插画。
- [ ] 人物、小狗和球拥有暖白剪纸边与统一近距离投影。
- [ ] 姿态有定格感，空间位移连续且可逆。
- [ ] 首页最终站姿、服装和身份区位置正确。
- [ ] 小狗确实绕人物一圈后停下，而不是直接瞬移。
- [ ] 最终人物与小狗完全静止，没有持续漂浮或呼吸循环。

### 14.3 内容与交互

- [ ] 一级导航只包含五个已确认栏目。
- [ ] 导航只使用英文栏目名，页面和分区标题使用中文，不重复同义中英标题。
- [ ] 首页左上角是天气或回退信息，不是网站名称。
- [ ] 首页右侧只有一个 Blog 主视觉。
- [ ] 所有精选内容可以进入总览或详情。
- [ ] 键盘、触摸和无 hover 场景均可操作。
- [ ] 缺图、天气失败和脚本失败都有稳定回退。

### 14.4 测试视口

至少检查：

- 1440 × 900：设计基准；
- 1280 × 720：低高度桌面；
- 1920 × 1080：宽屏；
- 1024 × 768：平板边界；
- 390 × 844：移动端后续基准；
- reduced motion；
- 200% 页面缩放下的导航和正文。

## 15. 明确废弃的方向

以下内容只作为历史记录，不得继续用于新设计和实现：

- 日式料亭、木门拉开、室内小店场景；
- 以实体手账、书脊、翻页或桌面边框承载全站；
- 可自由拖拽和缩放的无限画布；
- 只靠场景物件进入栏目；
- 把整个首页做成单张栅格图片；
- 首页左上角展示网站名称；
- 一级导航中的 Thoughts、Studio、Cabinet、Drinks、Devices 或 Apps；
- 黄色卫衣、青色背包作为默认人物服装；
- 夏季人物携带背包或黄色托特包；
- 人物向镜头奔跑、撞击屏幕或视角突然翻转；
- 第一镜头同时出现球和狗，或狗先于球出现；
- 用 scaleX 临时翻转方向错误的 Sprite；
- 70% 日式杂志 + 30% 店铺隐喻的旧品牌比例；
- 将所有内容直接印在点阵背景、不建立暖白大纸阅读层；
- 每条内容一张悬浮纸卡或五张彩色便利贴导航；
- 将真实照片、栏目图标和正文 UI 全部水彩化；
- 粗大纯白表情包描边、大头吉祥物和通用日漫脸；
- 独立等宽元数据字体、多套手写字体和同义中英双标题；
- 动画结束后角色持续呼吸、漂浮、摇摆或眨眼；
- 在 CP0 或未通过对应检查点时提前引入 Rive；React、Three.js、PixiJS、Lottie、Lenis 与游戏引擎继续禁止。Rive 仅允许在 CP4 以原生 Web Runtime 制作隔离样片，并受水彩质感回退门禁约束。
- 5–7 秒整屏 Seedance 预渲染视频作为开场（D-116 / D-120 旧路线）：整屏生成会把草地、点阵纸与背景一并重绘，已因背景污染、方向与透视错误被拒收，不再作为启动页生产方向。

## 16. 当前执行结论

当前正式路线为：

> 开场执行 oil-motion 帧映射方案（D-121）：点阵纸、暖白大纸与草地由网页静态层
> 提供，Seedance 2.5 只在纯色键背景上生成角色语义动作，oil-motion 负责帧级生产
> 与滚动进度映射（alpha-atlas + DOM/CSS Sprite 首选，WebGL 为停止条件），程序负责
> 横向几何与牵引绳，末段暖白纸遮罩无缝交接 Home v2 的实时人物与嘉乐（Rive Web
> Runtime 优先，水彩质感门禁未过则回退 16 方位统一枢轴 WebP Sprite）。当前处于
> CP0.5：架构与文档同步；关键帧与 Identity Bible 确认前，不生成 Seedance 动作、
> 不制作图集，也不改动动画实现。A1 的 `/lab/intro` 滚动 Sprite 实验保留为可运行
> 基线与动作参考，不再是开场方向。

现阶段不接入域名、不迁移全部旧内容、不制作冬季动画；CP1 起按检查点逐阶段推进，通过出口条件后才进入下一阶段。所有新设计应先通过本规范的视觉、动线、可访问性和回退规则。
