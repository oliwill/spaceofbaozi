# BaoziSpace 书影音设计稿

版本 1.0 · 2026 年 10 月 5 日 · 待审阅

## 这次要做什么

在现有网站中增加一个安静、好翻阅的「书影音」栏目，把你近二十年的豆瓣标记整理为自己的长期档案。访客能先看到近期记录，再按年份回看；每条记录的评分和短评留在站内，豆瓣链接只是补充入口。

页面沿用目前的暖白纸面、炭黑文字、点阵环境、左侧导航和人物关系。顶部只写「书影音」，下面是年份、小型日历热力图与时间倒序的记录。本文是完整设计提案，供你审阅；尚未实施，也不包含实施计划或上线批准。

## 审阅摘要

**已确认的样子**：顶部只写「书影音」，年份和小型灰阶日历在上，时间倒序的记录在下。用「全部 / 书 / 影 / 音」文字筛选，每条有小封面、名称、我的评分和短评，完整记录留在站内。只公开读过、看过、听过，支持近期与近二十年归档。

**这次建议你确认四点**

1. 默认当前年；切换年份时，热力图和列表一起切换。每页 24 条，往年仍通过同一页头进入。
2. 主导航末尾加「05 书影音」。桌面沿用原左栏，手机在现有页头内改为全宽单行，保留字号和触控面积；这是新增第五项所需的局部调整，须看实际页面确认。
3. 历史安全导出先私下核对，再由你决定公开。本站隐藏优先于重导入，后续评论更新也先审后发。首版不建在线后台。
4. 短评全文在书影音详情展示；独立长评建议在 Blog 保留唯一正文，再从详情站内链接过去。

**还没确认的外部条件**：尚无你的豆瓣主页和真实导出样本，不能保证 RSS 可用、导出字段齐全或二十年历史完整。封面也需确认可用来源。主路径采用 Excel 或脱敏标记 JSON，RSS 仅作核验后的近期补充。

本稿只提交设计供审阅。确认后才写实施计划；真实数据公开和上线仍另行确认。以下是页面规则、数据边界与验收细节。

## 1 页面与阅读流程

### 栏目首页和年度归档

从导航进入「书影音」，直接看到当前年份。上方依次是栏目名、年份选择、小型热力图；下方是类型筛选和当年的记录列表。年份与筛选采用轻量文字控件，选中状态通过字色、下划线与明确的可访问名称表达。

列表按标记日期从新到旧排列，同日按可信时间排序，没有具体时间时使用稳定条目 ID 保持顺序。默认每页 24 条，使用普通「上一页 / 下一页」，不使用无限滚动。封面和标题共同指向站内详情，短评在列表中最多显示两行，详情保留全文。未评分显示「未评分」，不画成零星。没有短评则省略短评区域，不补写感想。

年份选择包含当前年与已有批准记录的年份。已核对且确实没有记录的年份可显示「无记录」；未覆盖的年份不能写成零。没有精确年份的条目进入「日期待补」，不混进当前年。所谓二十年是档案跨度目标，不能在拿到数据之前虚构起始年份、总数或完整率。

当前年无记录时仍保持当前年，不悄悄切到旧年。空态简短写「这一年还没有公开记录」，并在有历史记录时给出「查看最近有记录的年份」。没有任何获准内容时写「书影音正在整理。」，页面保持 noindex。

年份、类型、所选日期和页码都通过可链接的页面状态表达；刷新、复制链接、浏览器前进后退后均能恢复。改变年份、类型或日期时重置到第一页，切换类型保留仍有效的所选日期。对应状态由静态页面承载，日期页只为有公开记录的日子生成；具体 URL 命名由后续计划确定，不能依赖临时内存或客户端查询参数才能找到记录。

### 热力图

热力图统计的是「本站已公开记录的标记日」，不是实际读完、看完或听完的日期。补标记录落在有据可查的标记日；不能因为你后来补录一部电影，就把它推断为当天看完。图旁保留一句低调说明「按标记日期」，不使用完成量、连续打卡或年度成就等措辞。

- 一天一格，固定灰阶为 0、1、2、3、4 条及以上；提示中仍显示实际条数。
- 改变「书 / 影 / 音」筛选时，热力图和列表使用同一批记录。
- 点击有记录的一天，筛出当天记录并显示可清除的日期条件；切换年份清除旧的日筛选，保留类型。
- 点选日期后只筛列表，热力图仍显示整年的分布，选中日期有独立轮廓。再次点击选中日或使用「查看全年」即可清除。
- 历史年份包含完整日历；当前年的未来日期不可选择，不能把未来画成「零记录」。
- 没有精确到日的记录不入格，年度列表可显示日期待补的分组，并提示有多少条未计入日历。连年份也未知的记录只在「日期待补」中出现。
- 未完成历史核对时，以「已收录」口径说明范围。空格只表示目前没有收录的公开记录，不宣称那天没有读书、看电影或听音乐。

桌面显示紧凑年度日历。手机先给出全年十二个月的紧凑灰阶概览，点选月份展开可操作的日历；当前年默认展开当前月，历史年默认展开最近有记录的月份，无记录时为一月。其他月份可展开；每个日期都有文字等价信息，较小格子的点选也可通过月份展开后的大触控区完成。不把 52 周强行缩成难以点中的一条，也不让整个页面横向溢出。键盘可在日历中移动、选择日期，Tab 不应被数百个格子拖住；无脚本时保留月份和日期的普通链接。

### 站内详情

详情从上到下包括返回入口、作品名称、小封面、作品类型、我的评分、标记日期、完整短评，以及可选标签和已确认的基础资料。作者、导演、表演者、发行年份等缺失时直接省略。豆瓣总评分不进入首版展示，避免与「我的评分」混淆，也减少不必要的数据依赖。

书、影、音使用同一种安静的详情结构，不为每种类型增加不同装饰。封面保留原比例，唱片保持方形；没有封面时不建大空框、不生成仿制封面。无短评时只展示已存在的记录。

「豆瓣条目」是次要外链，打开前无需离开站内正文。长评如已获准整理为 Blog 文章，通过「阅读完整书评 / 影评」等站内链接进入。不存在长评时不显示这个入口。

从列表进入详情后，返回应恢复年份、类型、日期、页码和原列表位置；直接访问详情时，返回其所属年度，无日期的条目回「日期待补」。普通链接和浏览器返回均可用，不因页面过渡而重复跳转或抢走焦点。

## 2 与现有网站怎样衔接

当前网站是 Astro 静态站，使用共享 Shell、原生 CSS 和内容发布门禁。已有 books、music 归档路由与 movies 占位页，但尚没有本稿定义的统一档案模型、导入流程和热力图。

新栏目使用现有外壳和 Editorial 排版层，不重新启用旧书壳或额外嵌套一张纸。颜色继续使用环境色 #F0EFEA、纸面 #FAF9F6、正文 #292825 和次级文字 #686660；标题、正文、UI 的字体延续现有规范。

桌面维持既有 300 / 242px 左栏和导航字级。新增第五项后，人物相对最后一项导航的已认可留白继续保留；不借新增栏目修改人物素材、动作或启动页。手机五项导航全宽单行仍需保证至少 44px 高、可触达且不互相遮挡；不能用缩小现有文字来硬塞。

旧 `/books`、`/music`、`/movies` 及已有详情链接在逐项核实前保留。可对应到新记录的旧内容才建立明确的兼容链接或重定向；不能一概把旧长文跳到年度列表，不能因新栏目删除旧草稿。`/drinks` 不在此次书影音整合范围。

本稿依据源码 v25、实施报告 v26 和后续已确认的页面方向。现有开场与首页衔接已获你的认可，本次不重新设计；其他栏目已有的待验证事项也不能因书影音完成而视为解决。

## 3 历史数据从哪里来

### 建议的主路径

由你提供只包含书影音标记的 Excel，或经去除账号与登录信息的标记 JSON。先做私下导入预览，核对真实字段和覆盖范围，再生成公开候选。第一次不会把整个导出包直接变成网页。

豆伴是豆坟项目下的账号备份扩展，项目说明支持导出 Excel，且备份不包含图片文件。已检查的导出结构可提供状态、名称、简介、豆瓣评分、条目链接、创建时间、我的评分、标签、评论、可见性；Excel 不能据此被视为已有封面 URL。实际文件版本仍需逐列核对。[豆伴项目说明](https://github.com/doufen-org/tofu)，[已核验版本的 Excel 导出字段](https://github.com/doufen-org/tofu/blob/56a9801922f67ee82b72e62ee4606d0b78f4a8fc/extension/explorer.js#L1510-L1561)

**不要上传豆伴的完整备份 ZIP。** 原始备份可能包含账号信息、cookies 等登录凭据；本站只需要作品和标记字段。导入契约拒收账号备份、登录凭据及与本栏目无关的数据。[豆伴备份任务中的 cookies 处理](https://github.com/doufen-org/tofu/blob/56a9801922f67ee82b72e62ee4606d0b78f4a8fc/extension/services/Job.js#L69-L94)。使用导出工具不等于授权我们安装扩展、读取浏览器会话或抓取所有豆瓣内容。

豆瓣官方提供个人信息下载入口，位于 App 的「设置 → 个人信息管理 → 个人信息下载」。目前未核验其实际文件是否包含本栏目所需的完整字段和二十年记录，可作为备选输入，拿到文件后再判断兼容性。[豆瓣个人信息保护政策 六（五）](https://www.douban.com/about/privacy)

### 后续更新

先支持重复导入新的安全导出文件。每次导入生成新增、修改、重复、异常、待隐藏和无变化记录的摘要，再确认本次需要公开的变化。已公开的网站不在访客打开页面时请求豆瓣。

RSS 候选形式为 `https://www.douban.com/feed/people/用户ID/interests`。还没有你的主页链接，不能确认此地址对你的账号可用、包含哪些类型和字段、近期窗口有多长。只有核实后才启用近期增量；漏掉的历史变化仍依赖完整导出核对。RSS 中没有出现某条记录，绝不等于该条已删除。

没有找到可确认目前仍可申请、适合个人完整标记读取的官方 API 路径，因此首版不依赖它。这不等于豆瓣不存在任何 API。持续自动抓取、登录态采集和自动发布都不在首版承诺内；若后续确有可用且合规的数据通道，再单独确定启用方式与频率。

## 4 数据模型和日期规则

每个公开条目至少需要稳定身份、类型、名称、完成状态和公开批准。评分、短评、日期和封面均可缺失，不能为通过校验而补造。

| 信息 | 规则 |
| --- | --- |
| 身份 | 豆瓣来源、书影音类型、作品 subject ID 共同去重；状态不是 ID 的一部分 |
| 作品 | 名称必填；经核实的作者、导演、表演者等为可选信息 |
| 状态 | 内部保留源状态；公开只接受读过、看过、听过 |
| 我的评分 | 独立于豆瓣总评分；首版统一为 1–5 的整数星级，未知为 null |
| 标记日期 | 保存原值、精度和来源解释；日期不足到日时不能进每日热力图 |
| 评论 | 保留你提供的完整短评；站内编辑版与原始导入文本分开 |
| 封面 | 可选；记录来源和可使用依据，缺失不阻塞文字记录 |
| 可见性 | 源可见性与本站公开决定分开保存；本站隐藏决定优先 |
| 导入信息 | 来源版本、导入时间、最近见到的时间及变化摘要，仅供维护 |
| 关联文章 | 可选的已公开 Blog 链接，不复制长文正文 |

仅名称相同不足以自动合并作品；同一本书的不同版本、电影和同名原声不能混为一条。缺 subject ID 时先隔离检查，可在人工确认后生成本地稳定 ID。重新导入同一份文件不得增加记录、热力计数或重复详情页。

源中的零值必须经过格式解释：如果该格式用 0 表示未评分，规范化为 null；合法一星不丢失，无法解释的值进入异常报告。绝不拿豆瓣总评分代替你的评分。

日期只有年月日时原样保存，不进行 UTC 转换。含明确偏移的时间先保留原始值，再按统一档案时区转为日历日期；建议本站档案采用 Asia/Shanghai，此为显示规则提案，不推断你当时身处何地。没有偏移且来源时区不明的时间不擅自换算。当前年由同一档案时区决定。静态入口在构建时生成，跨年需要重新构建以更新默认年份；实施计划需明确触发方式。未完成跨年重建前仍显示实际已生成的年份，不能声称已自动更新。

第一次实际导入要核实「创建时间」到底代表标记创建还是其他事件，再映射为标记日期；不能直接称完成日期。只有年份、只有月份、无效日期、未来时间都单独处理。确有用户补充的完成日期可另存，但首版热力图仍统一按标记日统计。

同一作品重复备份只更新当前记录；源没有完整重读、重看历史时，不从多次导出推断出多次阅读或观看事件。历史导入版本是维护证据，不是新增消费记录。

## 5 导入和公开之间的边界

数据流为：

安全导出文件 → 私下校验与标准化 → 去重和变化预览 → 你确认公开范围 → 批准的公开快照 → Astro 静态页面。

各部分职责保持简单：

- **来源适配**只理解输入字段，不决定公开，也不顺手下载封面。
- **标准化与核对**产生稳定记录、问题清单和差异，不修改当前公开快照。
- **公开选择**保存首次批准、本站隐藏和明确的站内编辑覆盖。
- **页面模型**只消费公开快照，统一供列表、详情、热力图及所有输出使用。
- **维护记录**报告最近成功导入、来源覆盖范围与失败原因，不向访客暴露账号资料或原始文件。

首次导入默认待审。可按批次批准明确范围内的完成记录，但私密、未知可见性、缺失身份和异常条目必须留在待审区。格式合法不能代替内容批准。

后续导入按来源新旧核对，旧备份不能静默覆盖新版本。已批准记录的新评分或评论先产生待审修订，当前公开版本保持，直到批准替换。你在站内明确改过的文字不会被重复导入覆盖；冲突列出来处理。

你已在本站隐藏的记录具有持久否决标记，之后重新导入仍然隐藏。豆伴已核验版本的变化比较没有把单独的可见性变化作为更新条件，因此不能把它当作可靠的隐私同步；收到的可见性字段也可能不是最新状态。[标记更新比较逻辑](https://github.com/doufen-org/tofu/blob/56a9801922f67ee82b72e62ee4606d0b78f4a8fc/extension/tasks/interest.js)。每次导入仍独立检查提供的可见性，未知值不得推断为公开。可靠的新数据若表明已公开条目变成私密或不再属于完成状态，生成高优先级撤回项，未解决的撤回项阻断发布，下一次候选必须先排除这些记录；不自动把原评论恢复公开。维护提示明确写出线上旧版本是否仍可访问，不能把“已发现”或“已从候选排除”说成“已经下架”。

导出缺页、RSS 窗口滑动、条目变成不可访问都不能触发批量删除。保留已有记录并标记需要核对。源服务故障时网站继续展示最近获准的快照，维护侧清楚显示最后一次成功时间，不能伪装同步成功。隐私变化未被来源提供时无法即时获知；静态站上的下架也要经过更新发布才能生效。

取消公开应同时移除详情、列表、计数、热力图、站内搜索索引、结构化数据和 sitemap 中相应内容。未批准、私密与不存在的详情使用同样的普通 404；不能仅靠 noindex 或隐藏链接保护内容。

## 6 封面和内容安全

先把文字档案做好，封面缺失不会拖住导入。优先使用你提供且允许用于本站的图片或明确可用的图片来源。取得授权后可生成本地小尺寸变体，避免访客阅读时依赖豆瓣图床；未经确认不默认缓存、盗链或批量补图。

豆瓣的法律声明分别规定用户原创内容的权属、站内图片及条目信息的使用边界。导出技术上可行并不自动授予第三方封面、平台评分或他人内容的再发布权。本栏不导入其他人的评论，不复制作品简介来填空；需要使用的外部素材逐项确认。[豆瓣法律声明](https://www.douban.com/about/legal)

导入文本按纯文本或受限 Markdown 处理，禁用原始脚本、事件属性、iframe 和不安全协议。外链只允许核实的 http(s) 地址；来源 URL 不能变成任意网络请求入口。RSS 解析不允许外部实体，文件解析不执行 Excel 宏或公式，不接受路径穿越或无限大小输入。

## 7 性能与可访问性
